# Operator-controlled default Lika

The operator manager is `/app/avatar/`. It uses the relay's existing `X-Admin-Token`, kept only in page memory. Uploading a ZIP does not publish it. A separate confirmation publishes a validated set. Previous-set restoration and resetting to bundled artwork are explicit buttons. This does not write any account profile or replace personal studio faces, emoji avatars or own clips.

The archive contains `manifest.json` with a short `label`, five 768×768 WebP stills (`idle`, `working`, `waiting`, `happy`, `error`) and four silent 512×512 H.264 MP4 clips (`idle`, `working`, `waiting`, `happy`), each between ten and fifteen seconds. The service limits both upload and expanded bytes, requires the exact flat file list, rejects duplicate/missing/traversal entries, validates media headers, track count, dimensions, codec and duration. It does not prove artistic consistency, seamless motion or decoded pixel quality. Preview is required to assess those. Do not upload client documents to this brand-only store.

The storage root is `AVATAR_RELEASES_DIR`, defaulting to `avatar-releases` beside the relay database. Persist it with the database volume. Media sets have content-derived immutable IDs and per-file SHA-256 metadata. A completed set is atomically installed before it can be selected. `active.json` is atomically replaced; expected revision prevents conflicting requests within the relay process. Run one relay worker for this filesystem-backed publisher. For multiple publishing workers, add a shared transactional lock/store first. Back up the release directory with the database. Old sets are retained so published immutable URLs and rollback remain valid. Manual cleanup must preserve active and previous sets and account for client caches.

Public read-only endpoints: `GET /v1/brand/avatar` returns a non-cacheable active manifest; `GET /v1/brand/avatar/assets/{release}/{filename}` returns allowlisted immutable media. The public preview `/web/avatar-preview/?release=<id>` plays actual media only after a button press, including when reduced motion is enabled. Error stays a still. It never changes the active set.

Protected endpoints: `GET /v1/admin/avatar-releases`, `POST /v1/admin/avatar-releases/upload` with ZIP bytes, `POST /v1/admin/avatar-releases/publish` with `{release, expected_revision}`. A null release returns clients to their built-in appearance. Re-publishing uses the current revision; stale revision returns 409. The manager does not expose the administrator credential to the public manifest or media.

Client support: Cloud browser/PWA uses the public manifest; runtime web UI and desktop plugin source include an operator-avatar hook. Only default appearances fetch this look. Own faces and clips keep priority. Clients check about once a minute while visible, use local bundled media if the relay or a media file is unavailable, preserve internal `dragon` identifiers, and respect reduced motion. The PWA service worker caches the code shell, not the active manifest or dynamic brand media. Offline use retains the bundled Lika.

Older installed native clients have no reader for this protocol. They need one normal app update containing support before operator changes can reach them. Updating server assets alone cannot retrofit old clients. This change does not implement the reader in Android/iOS. No native installer was built. The admin page is honest about client support. Operator publication does not change any profile preference or silently distribute executable application code.

Verification: Cloud tests exercise valid uploads, invalid archives/media, authorization, publish/reset/rollback, immutable headers and concurrent stale revisions. Web check/typecheck/build and desktop typecheck validate source integration. Browser checks exercise actual preview playback and responsive layouts; operator publish/reset/rollback UI uses an isolated API double, not live customer publication. A no-network deployment canary tests media validation and authentication before relay activation. Keep acquiring, refunds and bot gateway overlays unchanged.
