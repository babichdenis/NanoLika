# Релей: стресс-тесты, пустые ответы и DeepSeek с картинками

Проверка и исправления 9–10 ноября 2026 года. Продолжение
[аудита маршрутизации](relay-routing-review-2026-11-09.md).

## Результат

Исправления установлены на работающем релее. Проверены HTTP readiness 200,
состояние контейнера healthy, установленный код, административное состояние
допусков и выбор четырёх проверенных маршрутов для запроса с изображением.
В проверенном окне после запуска нет traceback и ошибок фоновой проверки качества.
Контрольное уведомление владельцу через бота Лики принято Telegram (HTTP 200).
Бот не перенастраивался; релей использует его существующий HTTP-прокси.

## Что воспроизвелось

1. Старые версии Flash у разных поставщиков неодинаково работают с изображениями.
   В первом ограниченном прогоне Polza v4-flash и RouterAI v4-flash-0731 не прошли
   проверку картинки; RouterAI v4.1-flash-1017 прошёл. Неуспех проверки не доказывает
   постоянную неспособность модели: возможны отказ запроса или неверный результат.
2. Удалить широкие ALIASES было недостаточно: сохранённый canonical_model мог
   снова подмешать старую версию в современный Flash. Добавлена проверка собственного
   идентификатора оффера. Запрос конкретной старой версии продолжает использовать
   именно её; общего разрешения заменять актуальную версию старой больше нет.
3. При отсутствии маршрута с изображением API утверждал «модель не принимает картинки».
   Это неверный вывод: причиной бывают баланс, cooldown, каталог или отсутствие
   свежей проверки. Теперь это временная недоступность маршрута (503), без заявления,
   что DeepSeek не умеет видеть, и без списания за неисполненный запрос.
4. Служебные keepalive могли скрывать отсутствие ответа или завершения потока.
   Ограничены ожидание заголовков, полный непотоковый ответ, поток до первого
   содержательного события и полное завершение потока.

## Реальные проверки поставщиков

Для каждого маршрута отправлены четыре одинаковых синтетических запроса:
русская инструкция, арифметика в JSON, вызов record_result с проверяемыми аргументами,
PNG с красной левой и синей правой половиной. Разговоры клиентов не использовались.

| Поставщик | Собственный идентификатор модели | Текст | JSON | Инструмент | Картинка |
| --- | --- | --- | --- | --- | --- |
| RouterAI | deepseek/deepseek-v4.1-flash | Да | Да | Да | Да |
| Polza | deepseek/deepseek-v4.1-flash | Да | Да | Да | Да |
| DeepSeek | deepseek-flash | Да | Да | Да | Да |
| AITunnel | deepseek-v4.1-flash | Да | Да | Да | Да |

Котировка не означает наличие рабочего маршрута: остаются проверки баланса,
возраста цены, ограничений контекста, инструментов и временных блокировок.
Расчётный резерв стоимости этих 16 запросов — 1,2883 ₽ по котировкам, а не
подтверждённое списание поставщиков. Прогон ограничен бюджетом 5 ₽ по оценке;
расхождение фактической цены с котировкой этот предел само по себе не предотвращает.

## Массовые сбои

600 запросов, 60 реально одновременно ожидающих ответов имитатора, 1200 попыток
с учётом резервного поставщика. Десять видов отказа: ConnectError, ReadTimeout,
HTTP 503, HTTP 429, повреждённый JSON, пустой объект, пустые choices, пробельный
ответ, reasoning без итогового ответа, повреждённые аргументы инструмента.
Все 600 запросов получили правильный ответ от резервного маршрута. Отказавший
маршрут не отмечался успешным. Это проверка конкурентной обработки сбоев,
не измерение предельной производительности сервера и не нагрузка на реальные API.

Дополнительно проверены ошибки SSE до первого ответа, пустой DONE, повреждённые
структуры и индексы, оборванный поток после видимого текста, бесконечные keepalive,
зависание непотокового ответа, сборка аргументов инструмента из фрагментов,
совместимость старого function_call. После видимого вывода другой поставщик
автоматически не повторяет ответ: клиент получает ошибку завершения.

API-проверки подтверждают снятие удержания при отсутствии маршрута и отсутствие
списания за полностью неисполненный запрос. Отказ личного ключа (BYOK) не меняет
здоровье и баланс общего поставщика. Уже выданный частичный поток учитывается
по прежней политике; бесплатность любого оборванного ответа не обещается.

## Изменённое поведение

- HTTP 200 считается успехом только при пригодном ответе. Для SSE успех наступает
  после полноценного завершения, а не при получении заголовков.
- У сетевых отказов, 401/402/403/408/429/5xx появился временный cooldown маршрута.
  Повторная отметка proven не удваивает счётчик сбоев.
- Ценовой карантин, сведения о сбоях и последние инциденты сохраняются и видны
  администратору. Успешные измерения задержек сохраняются с ограничением частоты.
- Для общего deepseek-flash обязателен свежий допуск конкретной пары поставщик/модель
  по требуемым возможностям. Проверенная способность видеть перевешивает ошибочное
  «text only» в каталоге; изображение при этом не удаляется из запроса.
- После допуска учитывается состояние маршрута; затем расчётная стоимость.
  Измеряются задержка первого содержательного события потока и длительность.
- Допуски действуют 24 часа; ограниченный повторный прогон настроен каждые 12 часов,
  до четырёх маршрутов, с расчётным бюджетом 5 ₽ за прогон. Контрольные данные не
  проходят через баланс клиента и не сохраняют его сообщения.
- Предупреждения о цене, повторных сбоях и провале проверки возможностей идут
  владельцу в Telegram. Для повторных сбоев есть порог и ограничение частоты.

Пределы ожидания на одну попытку: 30 с для заголовков потокового ответа, 90 с для
полного непотокового ответа, 30 с для начала содержательного потока, 180 с для
завершения потока. Время цепочки резервных попыток может быть больше.

## Проверка кода

133 проверки маршрутизации/отказов/BYOK и 90 проверок API, учёта и каталога.
Ruff check для изменённых файлов и проверка форматирования новых модулей,
маршрутизатора и тестов. Тесты не обращаются к реальным поставщикам.

Из корня исходного проекта:

```sh
cd cloud
python -m pytest -q tests/test_route_quality.py tests/test_route_stress.py \
  tests/test_route_api_failures.py tests/test_provider_routing.py \
  tests/test_deepseek_routing.py tests/test_byok.py tests/test_cloud.py \
  tests/test_allowance.py tests/test_audit_regressions.py tests/test_chat_catalog.py
ruff check nanomuse_cloud/provider_routing.py nanomuse_cloud/route_quality.py \
  nanomuse_cloud/route_probe.py nanomuse_cloud/api.py tests/test_route_quality.py \
  tests/test_route_stress.py tests/test_route_api_failures.py tests/test_provider_routing.py
```

Платный прогон запускается отдельно, без --run по умолчанию только показывает план:

```sh
python -m nanomuse_cloud.route_probe --output /private/route-quality.json \
  --model deepseek-flash --max-routes 4 --budget-rub 5
# Добавить --run только для реальных запросов с рабочими ключами поставщиков.
```

## Развёртывание и откат

Резервная копия перед изменением: серверный каталог
`/opt/nanomuse/cloud/backups/routing-quality-20261109-930b0f/`.
Сохранены прежние смонтированные provider_routing.py, api.py, Compose и кэш;
согласованная SQLite-копия — в закрытом каталоге data/.routing-backups.

Изменены именно установленные Python-модули работающего контейнера, а не только
дерево исходников. Для route_quality.py и route_probe.py добавлены постоянные mounts
в оба Python-корня. Существующие mounts перезаписаны с сохранением inode.
Ключи уведомлений находятся в закрытом env-файле и не включены в этот отчёт.
Подключение к сети существующего прокси сохранено в Compose для будущих запусков.

Исходники и тесты синхронизированы с проектом приложения. Чужие изменения веб-UI
не затрагивались. Версии приложения и установщики не пересобирались.

Для отката восстановить прежние Python-файлы и Compose из резервной копии,
пересоздать только relay и проверить healthz. Не восстанавливать старую SQLite
поверх работающей базы: это потеряет новые сообщения и платежи. Дополнительное
сетевое подключение прокси при откате будет убрано пересозданием контейнера.

## Что пока не доказано

Строгий эмпирический допуск развёрнут для общего DeepSeek Flash. Остальной каталог
не прошёл такой же полный прогон. Все модели получили общую проверку пригодности
ответа и обработку сбоев, но это не сертификат их смыслового качества.

Четыре коротких задания — проверка базовых возможностей, не полноценный рейтинг
качества. Большие документы, длинный контекст, сложные изображения, несколько
инструментов, качество рассуждений и длительные деградации требуют отдельного
набора задач и статистики. Успешный текущий прогон не гарантирует неизменность
поведения поставщика завтра; поэтому допуски истекают и проверяются повторно.
