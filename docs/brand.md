# NanoLika brand

The application uses the approved website's warm paper and sage identity.

## The mark

The launcher, startup screen and sign-in mark are fairy wings on an ivory tile.
The source is `assets/brand/nanomuse-mark.svg`; `nanomuse-icon.svg` adds the tile.
The historical filenames remain stable for packaging. The blue N artwork was replaced.
The mascot in conversation headers is the full-body Lika fairy from the website.
The internal profile value remains `dragon`, including existing accounts. Studio faces,
emoji avatars and a person's own clips retain their existing behaviour.

Coral and amber are restrained illustration and status details. The app retains readable
system/sans typography for controls and long conversations. The website's handwritten
art direction belongs to the artwork, not to every line of chat.

The factory appearance is light paper. A saved light, dark or system choice takes priority.
The desktop Host uses its existing `ui-theme` settings with a light factory preference.
The phone defaults are generated by `scripts/nanolika_theme.py`, called by `rebrand.py`.
The web uses semantic tokens in `web/src/index.css`, the desktop in `styles.ts`.

## Assets and regeneration

The canonical stills and silent clips are in `assets/brand/avatar/`.
The fairy's entire seated figure, shoes and wings fit inside the circular frame.
Clips use H.264 MP4; stills remain the fallback for small views, errors, unavailable
video and reduced motion. Mood timing and profile navigation remain unchanged.

`python scripts/sync-brand.py` regenerates icon resources and synchronises avatar files
across Android, iOS, the desktop plugin and web sources. Rebuild the web app afterwards:
`cd web && npm run build`. The generated runtime web bundle is committed.

The renderer uses an existing Node/Sharp installation. `NANOLIKA_NODE` and
`NANOLIKA_SHARP_MODULE` may point to an existing toolchain. It installs nothing.
The abandoned logo-exploration kit and unreferenced upstream iOS icon variants were removed.
Historical documentation screenshots and third-party/upstream attribution assets remain
historical records. They are not shipped as the current application identity.

## Verification and cleanup

Packaged avatar copies are checked by `tests/test_brand_assets.py`.
The new clips replace the old dragon videos as well as their poster images.
The obsolete logo exploration PNGs and unreferenced `Icon-full*.png` iOS candidates
were removed; normal interface glyphs, third-party attribution and historical screenshots
were retained. Vite rebuilds the runtime web directory and removes obsolete hashed bundles.

Web lint, types, tests and production build passed. Desktop plugin build, types and tests,
and desktop shell type checking passed. The phone palettes were regenerated and checked
for idempotence. Native phone builds still require a machine with Java/Android tools and
full Xcode; those native builds were not run in this workspace.
