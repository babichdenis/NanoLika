# Склад: что клиентская модель берёт с сервера, а не из установщика

Установщик NanoLika Desktop — это то, что человек скачал один раз и обновляет. Всё, что нужно
редко и весит десятки мегабайт (OCR, PyMuPDF, тяжёлые MCP-серверы), в него не кладётся: это
**склад** на `cloud.nanolika.ru`, устроенный как маленький репозиторий пакетов.

Модель обязана сначала посмотреть склад — не искать в интернете и не пытаться `pip install`
в замороженном рантайме (там нет pip).

## Что где лежит

| раздел | путь на сервере | что это |
|---|---|---|
| навыки | `/opt/nanomuse/cloud/store/skills/<name>/SKILL.md` | обычный SKILL.md в формате Agent Skills; сервер отдаёт только текст |
| капсулы | `/opt/nanomuse/cloud/store/capsules/<name>/<version>/<platform>.zip` | zip с python-кодом и, если нужно, данными; распаковывается в `<data_dir>/addons/<name>` |
| MCP | `/opt/nanomuse/cloud/store/mcp/<name>.json` | описание сервера: имя, команда или url, риск, что даёт |
| каталог | `/opt/nanomuse/cloud/store/index.json` | единый список: чем можно закрыть дырку, сколько весит, под какие платформы |

Публичные адреса (через Caddy, `handle_path /store/*` → `/srv/store`):

- `https://cloud.nanolika.ru/store/index.json`
- `https://cloud.nanolika.ru/store/skills/<name>/SKILL.md`
- `https://cloud.nanolika.ru/store/capsules/<name>/<version>/<platform>.zip`
- `https://cloud.nanolika.ru/store/mcp/<name>.json`

## Как рантайм это использует

1. **Инструмент `store`** (`nanomuse/tools/store.py`) — единственный вход для модели:
   - `store` `action=list` — что есть в каталоге (с фильтром по тому, чего не хватает);
   - `store` `action=install` `name=ocr` — скачать капсулу под эту платформу, проверить sha256,
     распаковать в `<data_dir>/addons/<name>`, включить в `sys.path`;
   - `store` `action=skill` `name=...` — поставить навык со склада (то же, что импорт по ссылке);
   - `store` `action=status` — что уже стоит.
2. **Промпт** (`prompts.STORE_SECTION`) перечисляет, чего в этой сборке нет, и говорит: бери
   со склада, не из интернета. Раздел собирается на каждом запросе из фактического состояния
   (`store.missing()`), поэтому после установки строка исчезает.

## Капсула: что внутри

```
capsule.json     имя, версия, платформы, что даёт, какие модули импортирует, sha256 файлов
__init__.py      точка входа: register(...) или просто модули, которые импортирует рантайм
...              код, данные, модели
```

Правила:

- только чистый python и данные; ничего, что требует компиляции на машине клиента;
- одна капсула — одна платформа-независимая функциональность или отдельные zip на платформу
  (`darwin-x64.zip`, `win32-x64.zip`);
- `sha256` каждого zip лежит в `index.json`: рантайм сверяет до распаковки;
- капсула не имеет права писать вне `<data_dir>/addons/<name>`.

## Как положить новое (для нас, не для модели)

```sh
# 1. собрать каталог капсулы локально, сложить в store/capsules/<name>/<version>/
# 2. пересчитать индекс
python3 cloud/scripts/store_index.py            # пишет store/index.json и печатает размеры
# 3. выложить
rsync -a cloud/store/ root@151.248.123.86:/opt/nanomuse/cloud/store/
```

Индекс — единственная истина о том, что есть. Руками файлы в `store/` не кладутся: они попадут
на сервер, но модель о них не узнает.
