# 隐私与数据流向

本页介绍软件行为，不保证每个部署均符合法律要求。nanoLika 运营者的专用说明
准备发布在 [nanoLika 网站](https://nanolika.ru/privacy.html)。网站修订和服务器
防护需要分别部署。自行部署时，应按实际基础设施制定规则，不能直接套用其他运营者的声明。

## 本地数据与云端数据

本地运行时可以在用户设备上保存对话、记忆、文件、计划任务、技能和设置。
这不意味着所有数据都留在设备。模型请求可能发送消息、历史上下文、附件及工具结果。
云端登录、对话同步、远程备份和连接器会产生其他数据流。服务器上的 Telegram
运行时在该服务器上处理和保存数据，而不是只在用户手机上处理。

## 中继

中继可以保存账号标识、加密联系方式、密钥散列、设备资料、头像及连接器元数据、
用量和财务记录、事件、网络地址及客户端信息。运营者能够解密的数据不是匿名数据。
使用同步功能时，对话内容也会到达中继。API 和账号控制见 [Cloud](cloud.md)。
本页不承诺固定免费额度、非营利性质或统一的模型供应商，具体条件由实际运营者公布。

## 模型供应商与通信渠道

云端供应商处理实际收到的上下文，可能包括历史消息与工具结果，不仅是最后一句话。
nanoLika Cloud 是服务名称，不表示运营者开发了底层模型。自备密钥请求受所选供应商
的数据规则约束。Telegram 是具有独立基础设施和条款的服务。境外传输节点仍需检查
TLS 终止、缓冲区、日志和连接元数据。只迁移数据库不会迁移其他服务器上的机器人或工作目录。

## 可选对话样本

新账号默认关闭额外的样本收集。`IMPROVE_DEFAULT` 不再启用此功能，用户需要在
数据控制中单独开启。旧的默认开启事件不能授权新的采集。此目的不同于提供回答、
保存历史或同步。开启后，样本可包含用户文字、模型回答和工具调用参数。
样本过滤会去掉系统提示、工具结果消息和图片、音频、视频内容，但保留的文本仍可能
包含个人信息。导出时去掉账号 id 不一定使内容匿名。运营者可以在管理控制台查看样本。

关闭开关会停止后续收集。删除样本和删除账号是独立控制。此次代码修改不会自动删除
已有样本。此额外目的仍需合法依据和充分告知，软件开关不能替代这些要求。

## 准备、保留与请求

`REGISTRATION_HOLD=1` 会在验证码保存或发送前阻止新的登录标识，覆盖普通登录、
机器人和新标识关联。现有用户继续使用。为兼容现有部署，默认是 `0`，运营者需要
明确开启并重启。它不会迁移数据，也不证明合规。公开注册前，应核实收集地点、处理方、
跨境传输、通知、保留期限、权限和删除，包括附件、审计日志、备份和法定财务记录。
