## 3. Дыры (по убыванию важности)

### D1. Приёма платежей нет вообще
Grep по всему репо: ни Т-Банк/Т-Бизнес, ни СБП/QR, ни epay/stripe/creem/monetix/ЮKassa
как платёжек — ноль совпадений (Stripe встречается только как MCP-коннектор каталога).
Единственный способ положить деньги — оператору руками через admin credit.
При этом **тексты обещают подписку**: RU-консоль `cloud/console/app.js:37,50` —
«оформите подписку — и лимит снова полный», `providers.py:145-148` — «renew your
access with a subscription»; механизма нет ни в консоли, ни в десктопе (нет
top-up-ссылки, нет действия `top-up` в refusalCard). Комментарий разработчика
(app.js:581-583) прямо говорит: «the subscription when it comes».

### D2. «The operator has been told» — фраза без механизма
Копия фразы живёт в 6 местах (api.py:274,278; refusals.ts:232; failures.py:54;
locales.ts en/ru; web/src/i18n/zh-CN.ts:1469), а механизма нет:
- `controls.notify` (email/SMTP, ADMIN_EMAIL) дёргается **только** от порогов по
  числу аккаунтов (controls.py:226,233) и notify-test (api.py:1700);
- selfcheck.sh (deploy/nanomuse-hk/selfcheck.sh:16,40,101-109) шлёт JSON в
  `ALERT_URL` (Feishu/Slack-вебхук) — но только на падение healthz, не на бюджет;
- на `upstream_budget`/`upstream_auth` не завязан ни один канал уведомления.
Итог: 2026-10-20 оператор узнал об отказах от пользователя, а не из системы.

### D3. Баланс апстрима не мониторится, и управляется он костылями
- Релей не читает баланс new-api вообще: исчерпание распознаётся реактивно по
  тексту ошибки (`upstream_budget_refusal`, api.py:220-247). Никакого polling'а нет.
- new-api молча ушёл в минус и отравил чат всем пользователям до ручного вмешательства.
- Поправить квоту штатно нельзя (см. §0): sqlite + рестарт контейнера.
- IP в logs new-api пустые (запросы идут изнутри докер-сети) — атрибуция «кто именно
  сжёг» по IP невозможна.

### D4. Учёт расходов расходится на порядки — цены нельзя выставлять
За 7 дней по токену id=2: new-api **списал $1 000.93** (558 запросов), релей
**начислил пользователям ¥7.23** (524 запроса). По дням new-api:
| День | Запросы | Списано |
|---|---|---|
| 16.10 | 4 | $0.04 |
| 17.10 | 104 | **$757.79** |
| 18.10 | 66 | **$242.32** |
| 19.10 | 8 | $0.01 |
| 20.10 | 353 | $0.76 |
Гипотезы (нужно закрыть ДО запуска оплаты, иначе цена «бесплатного» allowance ложная):
1. ratio в new-api для `deepseek-v4-pro` завышен (84 запроса = $6.8/request);
2. токен id=2 используют ещё потребители (ключ лежит в /opt/ai-bridge/data/,
   мосты на другом берегу; внутри докера IP не различить);
3. релей считает по листовым ценам, new-api — по своим ratio, и это не одно и то же.
Способ проверки: сверить `used_quota` до/после серии из N контролируемых запросов
через релей и напрямую.

## 4. Рекомендуемый контур оплаты (дорожная карта)

**Этап 1 — честность и мониторинг (1 день, без провайдеров).**
- Cron на сервере: читать `quota` root из new-api (API или sqlite), шлёт в
  `ALERT_URL` при < порога (например, $5 и $1).
- Дёрнуть notify на `upstream_budget`/`upstream_auth` (тем же ALERT_URL или SMTP).
- Убрать/смягчить «operator has been told» до момента, пока это правда.
- Разобраться с D4 (сверка ratio new-api с листовыми ценами релея).

**Этап 2 — ручной приём платежей (2-3 дня).**
Самый быстрый для РФ: **Т-Бизнес QR / СБП** (нужен ИП/самозанятый/ООО):
- статичный QR + сумма → человек платит → оператор жмёт «зачислить» →
  `POST /v1/admin/credit` (уже существует, менять ничего не надо);
- либо уже существующая кнопка в админке, если деньги идут на пул конкретного
  аккаунта по телефону/e-mail (cloud/README.md:815).

**Этап 3 — автоматизация (неделя).**
- Страница «Баланс/Пополнить» в консоли оператора (текущий остаток new-api,
  история credit) и ссылка «Пополнить» в десктопе (отказ `exhausted` →
  deep-link на страницу оплаты, refusals.ts добавляет действие `top-up`).
- Вебхук/подтверждение: Т-Банк (API Т-Бизнес) или ЮKassa/CloudPayments →
  авто-`admin credit` с audit-привязкой к платежу. Здесь решается вопрос чеков
  (54-ФЗ), если это ИП/ООО.

**Этап 4 — подписка (обещание из текстов).**
Периодическое начисление (месячный пул или unlimited на период) поверх того же
admin credit. Тексты в консоли уже готовы под этот сценарий.
