# 聊天渠道权限

Telegram 和 MAX 的审批卡可提供仅此一次、此对话、始终允许此操作，且只显示待审批请求实际允许的范围。权限绑定工具和目标，并非所有操作的无限授权。带风险警告的操作仍须逐次确认。回调必须来自配对用户、原始聊天及原始待审批卡；不能扩大范围或重放已解决的卡片。

服务器机器人与桌面端分别保存权限，不自动复制。电脑任务由接收设备继续检查权限。仅使用 Telegram 的用户也可在审批卡保存长期权限。长期权限可在运行时权限设置中撤销。

助手可以在明确提供的工作目录内编写按钮与网页代码，但这不自动提供生产服务器权限、机器人凭据或修改自身安全策略的能力。


## 易读审批卡

俄语卡片展示操作类别、已有任务目的、路径或收件人及风险提示，不因命令包含已知程序就声称它安全或只读。技术命令预览放在详情按钮中；查看详情不会批准请求，原审批按钮仍保留。详情也检查配对用户、聊天与待审批卡，过期后不可访问。常见凭据格式会被遮盖并限制长度，但无法保证识别代码中的任意秘密；缺失的操作目的不会被编造。

详情通过编辑原 Telegram/MAX 审批卡展开，决定按钮保留在详情下方，不再单独发送详情消息。消息引用缓存在有限内存中；缓存缺失时发送包含详情与审批按钮的新卡片。

## 重启后可用的私人菜单

Telegram/MAX 的主页、权限、余额和语言导航使用稳定标识。改变权限等敏感按钮仍使用短时、一次性令牌，绑定已配对用户及私人会话。过期按钮只重新显示菜单并解释，不授予权限。群聊或未配对请求显示私人配对说明。完全访问仍需确认，桌面与共享服务器的权限不自动合并。MAX 在处理已验证回调前调用 `/answers` 确认。

经过运行时身份验证的 `POST /api/channels/{telegram|max}/menu` 通过正在工作的管理器向明确配对的拥有者发送菜单。它不是公开接口，不改变权限。多个拥有者时必须指定目标。
