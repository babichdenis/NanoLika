# NanoLika 0.1.19 · Ensemble

Every device you own, and the browser when you own none of them: the phone, the computer and the web are one Muse.

**NanoLika is a fully open-source, non-profit community project, built to make a better personal agent together, and it will never charge for anything.** Sign in with an e-mail address or a phone number and the agent has free model access, about ¥25 (≈ $3.5) a day per account: paid for by the developer. Your messages are not stored by the relay and nothing about you is sold or shared; delete the account at any time, or bring your own API key and skip the relay altogether.

## Added

- **nanoMuse Web, nothing to install.** Sign in at [nanomuse.cn/web](https://nanomuse.cn/web/) with an e-mail or a phone code and you get a nanoMuse of your own on the project's server: kept between visits (it sleeps after six quiet hours and wakes when you come back), signed in to your account as the device *Web*, with the Cloud as its model. It sits on the hub with your phone and computer, so it can ask them for things and they can ask it. The data stays in a container only you can reach.
- **NanoLika for the desktop: the window.** A desktop app for Windows, macOS and Linux shaped after the phone app, with the runtime inside: a face, one main chat and side chats, Devices, approvals in tiers, and hands on the computer's own screen, with the **stage** drawn over the display while they work (the ring where a click is about to land, a drag line, a pill with the step) and `Ctrl/Cmd+Shift+Esc` as a global Stop. It lives in the tray and keeps the runtime alive. On screens 1024 px and wider the web app grows a sidebar: the agent and its status, the sections, the chats and the devices a chat can be addressed to.
- **The computer on the hub, both ways.** `nanomuse serve` signs in to NanoLika Cloud, answers the account's other devices (`shell`, `files`, `open`, `screen`, `notify`, a whole `task` in a visible side chat *From <device>*) and reaches them with the same tools it has for itself: `device_shell`, `device_files`, `device_screen`, `delegate`, … Progress travels as `tool`, `tool_result`, `approval` and `approval_result` frames, so an approval asked on one device is answered on the device you hold.
- **Hands on this computer.** The phone operator loop over a computer: the screen, the mouse and keyboard, the active window, Qwen's `computer_use` dialect; `computer_screen`, `computer_act`, `computer_task`, judged by the Sentinel like everything else. Off by default.
- **The phone, catching up.** The app reads the runtime's stages, relays its own Sentinel approvals to the device that asked and takes the answer back, and shows a *Devices* row in the drawer with how many other devices are online.
- **The terminal binary.** `nanomuse-desktop-terminal-<v>-…`: Windows setup, macOS pkg, Linux deb and tar.gz, for a `nanomuse` in the terminal and `nanomuse serve` for the same app in a browser and on the phone.

## Fixed

- A remote approval answered from the web app went to the local gate instead of the hub; it now travels back to the device that asked, and the card closes on both sides.
- A delegated task's final answer was lost when the target's chat finished before the caller read it.
- `.webp` avatars were served as `application/octet-stream` on systems without the type registered.
- A Cloud key kept in the vault showed as *missing* under Connections.
- The 0.1.18 notes mentioned desktop installers that were not on the release; this one has them.

## Install

| | |
|---|---|
| Browser | [nanomuse.cn/web](https://nanomuse.cn/web/): an e-mail or a phone number |
| Android 8.0+, arm64 | `NanoLika-0.1.19-arm64.apk`: same signing key, installs over 0.1.18 (versionCode 20); `sha256sum -c NanoLika-0.1.19-arm64.apk.sha256` |
| Windows 10+ | `NanoLika-Desktop-0.1.19-win-x64.exe` (the app) · `nanomuse-desktop-terminal-0.1.19-windows-x64-setup.exe` (terminal) |
| macOS 12+ | `NanoLika-Desktop-0.1.19-mac-arm64.dmg` / `-mac-x64.dmg` (the app) · `nanomuse-desktop-terminal-0.1.19-macos-arm64.pkg` / `-x64.pkg` (terminal) |
| Linux x64 | `NanoLika-Desktop-0.1.19-linux-x64.AppImage` / `.deb` (the app) · `nanomuse-desktop-terminal-0.1.19-linux-x64.deb` / `.tar.gz` (terminal) |

The desktop installers are not code-signed: macOS asks for right-click → *Open* once, Windows for *Run anyway*. `SHA256SUMS-desktop-app.txt` and `SHA256SUMS-desktop-terminal.txt` list every checksum. The installers arrive a little after the APK: CI builds them from the tag.

你的每一台设备，以及一台都没有时的浏览器：手机、电脑和网页是同一个 Muse。

**NanoLika 是纯开源、非营利的社区项目，目标是和社区一起做出更好的个人智能体，永远不会收取任何费用。** 用邮箱或手机号登录，就能免费使用模型，现阶段每个账号每天约 ¥25（≈ $3.5），模型费用由开发者自己承担。中转不保存你的消息，你的任何数据都不会被出售或分享；随时可以删除账号，也可以直接用自己的 API key，完全不经过中转。

### 新增

- **nanoMuse 网页版，什么都不用装。** 在 [nanomuse.cn/web](https://nanomuse.cn/web/) 用邮箱或手机验证码登录，就有一台属于你的 nanoMuse 跑在项目的服务器上：下次来还在（闲置六小时后休眠，你回来时唤醒），以「Web」这台设备的身份登录你的账号，模型走 Cloud。它和你的手机、电脑在同一个 hub 上，可以互相拜托。数据留在一个只有你能访问的容器里。
- **桌面版，带窗口的 NanoLika。** Windows、macOS、Linux 的桌面 App，形状和手机版一样，运行时打包在里面：形象、一个主对话加旁聊、设备、分级审批，以及在电脑自己屏幕上的 Hands，干活时屏幕上有 **stage**（即将点击处的圆环、拖动的轨迹、写着当前步骤的胶囊），`Ctrl/Cmd+Shift+Esc` 是全局的「停止」。它待在托盘里，让运行时一直活着。1024 px 以上的屏幕，网页 App 多出一个侧栏：智能体和它的状态、各个板块、对话，以及对话可以指向的设备。
- **电脑在 hub 上，双向。** `nanomuse serve` 登录 NanoLika Cloud，响应同一账号下其他设备的请求（`shell`、`files`、`open`、`screen`、`notify`，以及在可见的旁聊「来自 <设备>」里执行的一整个 `task`），也用同一套工具去拜托它们，`device_shell`、`device_files`、`device_screen`、`delegate`……进度以 `tool`、`tool_result`、`approval`、`approval_result` 帧传递，所以在一台设备上发起的审批，在你手里的那台设备上回答。
- **电脑上的 Hands。** 把手机的操作循环搬到电脑上：屏幕、鼠标键盘、当前窗口、Qwen 的 `computer_use` 方言；`computer_screen`、`computer_act`、`computer_task`，和其他一切一样由 Sentinel 审查。默认关闭。
- **手机跟上。** App 能读运行时的各个阶段，把自己的 Sentinel 审批转给发起的那台设备并接回答复，抽屉里多了「设备」一行，显示有几台其他设备在线。
- **终端版。** `nanomuse-desktop-terminal-<v>-…`（Windows 安装包、macOS pkg、Linux deb 和 tar.gz），终端里的 `nanomuse`，以及 `nanomuse serve` 把同一个 App 开在浏览器和手机上。

### 修复

- 在网页 App 里回答的远程审批走到了本地的门，而不是 hub；现在会回到发起的那台设备，两边的卡片一起关闭。
- 被委托的任务在对方对话结束得比发起方读取更早时，最后的回答会丢失。
- 系统没注册 `.webp` 类型时，形象图片被当成 `application/octet-stream` 返回。
- 保险库里的 Cloud key 在「连接」页显示为「缺失」。
- 0.1.18 的说明提到了当时并不在 release 里的桌面安装包；这一版有了。
