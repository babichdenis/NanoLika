# NanoLika 0.1.21 · Footing

Nothing new to demonstrate, a great deal more to trust. A pass over every part of NanoLika (the runtime, the relay, the web app, the desktop, the phone, the docs) so that failures are said plainly, money is counted once, secrets stay where they belong, and the apps pick themselves up.

**NanoLika is a fully open-source, non-profit community project, built to make a better personal agent together, and it will never charge for anything.** Sign in with an e-mail address or a phone number and the agent has free model access, about ¥25 (≈ $3.5) a day per account: paid for by the developer. Your messages are not stored by the relay and nothing about you is sold or shared; delete the account at any time, or bring your own API key and skip the relay altogether.

## What changed

- **Failures in one sentence.** When a run fails, the card says what happened (the key was refused, the allowance is used up, the provider is busy, the model does not exist, the stream broke) with the technical detail under *Details*, instead of "Something went wrong: <exception>". The relay stopped forwarding its provider's error texts (an "Incorrect API key" you may have seen was the relay's key, never yours). On the phone, hub and coding errors are sentences in English, 简体中文 and 繁體中文.
- **NanoLika Cloud, as what it is.** Signed in, the model form offers *NanoLika Cloud* by name under *Your account* (the chat models the account can use, the recommended one first, no key or URL to paste) and the summaries read "NanoLika Cloud · qwen3.8-27b" instead of a relay address.
- **Counted once.** A request the provider refused before answering used to be charged its estimated prompt; it no longer costs anything. A retried video poll can no longer bill a clip twice. (Relay 0.3.2.)
- **Kept out of reach.** The relay compares the operator's token in constant time and fetches pictures only from its provider's own hosts, so it cannot be pointed at its own network. On the phone, the pairing tokens for your computers moved into the encrypted store, and no secret store goes into a device backup or transfer; another app can no longer post alarm notifications through NanoLika. The runtime's browser tool refuses local and LAN addresses the way page fetches already did.
- **Picking themselves up.** The web app says *Connecting…* until the runtime answers, puts your draft back when a send fails, shows an empty chat with a note instead of nothing when history could not load, offers *Retry* where the first run stalled, and ends a call when the allowance or the length limit is reached. The desktop app restarts a runtime that died, once on its own and then with a dialog that opens the log; startup failures name their usual causes. On the phone, a hub that was refused by the relay says so under Devices instead of reconnecting forever, and the background service asks for the notification permission it needs on Android 13+. During a call the camera can be switched on and off, and the screen stays on.
- **About and updates.** The desktop tray has *About NanoLika* and *Check for updates*; a `pipx` or Docker runtime says under *Settings → About* when a newer release is out (once every six hours, from GitHub Releases, nothing downloaded, nothing sent; `server.update_check = false` turns it off). The window opens where it was closed.
- **Under the hood.** Event timelines are written off the event loop in coalesced batches, and the coding-agent routes probe CLIs and folders in a thread, so a busy runtime stays responsive. `nanomuse serve` explains a broken `config.toml` or an unwritable data folder in a sentence. Every web screen but the chat is a lazy chunk. Screens and cards that had raw or English-only text in the Chinese UI now read Chinese.
- **Docs.** [docs/android.md](../android.md) describes the app you actually download, one arm64 APK, the account first, Hands, Reach, the hub, calls, coding agents, where the secrets live, how to build and release; the earlier Python-line pages carry a banner saying they are design records. The dragon is named as the default face everywhere.

## Install

| | |
|---|---|
| Browser | [nanomuse.cn/web](https://nanomuse.cn/web/): an e-mail or a phone number |
| Android 8.0+, arm64 | `NanoLika-0.1.21-arm64.apk`: same signing key, installs over 0.1.20 (versionCode 22); `sha256sum -c NanoLika-0.1.21-arm64.apk.sha256` |
| Windows 10+ | `NanoLika-Desktop-0.1.21-win-x64.exe` (the app) · `nanomuse-desktop-terminal-0.1.21-windows-x64-setup.exe` (terminal) |
| macOS 12+ | `NanoLika-Desktop-0.1.21-mac-arm64.dmg` / `-mac-x64.dmg` (the app) · `nanomuse-desktop-terminal-0.1.21-macos-arm64.pkg` / `-x64.pkg` (terminal) |
| Linux x64 | `NanoLika-Desktop-0.1.21-linux-x64.AppImage` / `.deb` (the app) · `nanomuse-desktop-terminal-0.1.21-linux-x64.deb` / `.tar.gz` (terminal) |

The desktop installers are not code-signed: macOS asks for right-click → *Open* once, Windows for *Run anyway*. `SHA256SUMS-desktop-app.txt` and `SHA256SUMS-desktop-terminal.txt` list every checksum. The installers arrive a little after the APK: CI builds them from the tag.

没有新的演示，多了很多可以放心的地方。这一版把 NanoLika 的每个部分（运行时、中转、网页 App、桌面版、手机版、文档），都过了一遍：出错时说人话，钱只算一次，秘密放在该放的地方，App 摔倒了自己站起来。

**NanoLika 是纯开源、非营利的社区项目，目标是和社区一起做出更好的个人智能体，永远不会收取任何费用。** 用邮箱或手机号登录，就能免费使用模型，现阶段每个账号每天约 ¥25（≈ $3.5），模型费用由开发者自己承担。中转不保存你的消息，你的任何数据都不会被出售或分享；随时可以删除账号，也可以直接用自己的 API key，完全不经过中转。

### 变了什么

- **出错只说一句话。** 一次运行失败时，卡片直接说明发生了什么（key 被拒、今天的额度用完、服务商忙、模型不存在、流中断），技术细节收在「详情」里，不再是「出了点问题：<异常>」。中转不再转发服务商的报错原文（你可能见过的「Incorrect API key」是中转自己的 key，和你无关）。手机上，多设备和 coding agent 的错误也是完整的句子，英文、简体、繁体各一份。
- **NanoLika Cloud，就叫这个名字。** 登录之后，模型表单的「你的账号」一组里直接列出 *NanoLika Cloud*，账号能用的对话模型，推荐的排第一，不用贴 key 和地址，摘要显示「NanoLika Cloud · qwen3.8-27b」而不是一个中转地址。
- **只算一次。** 服务商还没回答就拒绝的请求，以前会按预估的提示词计费，现在不花钱。重试的视频轮询也不会把一段视频算两次。（中转 0.3.2。）
- **够不着的地方。** 中转用恒定时间比较管理员令牌，图片只从服务商自己的域名取，因此没法被引导去访问自己的内网。手机上，配对电脑的令牌搬进了加密存储，任何一处存密钥的地方都不会进入设备备份或迁移；别的 App 也不能再借 NanoLika 发闹钟通知。运行时的浏览器工具和网页抓取一样拒绝本机和局域网地址。
- **自己站起来。** 网页 App 在运行时答话之前显示「正在连接…」，发送失败时把草稿放回输入框，历史加载失败时显示空对话和一条提示而不是一片空白，首次设置卡住的地方有「重试」，额度或时长到了通话就结束。桌面版会把停掉的运行时拉起来，第一次自己来，第二次弹窗并能打开日志；启动失败时说明常见原因。手机上，被中转拒绝的多设备连接会在「设备」里说明，而不是无限重连；后台服务在 Android 13+ 上会申请它需要的通知权限。通话中可以开关摄像头，屏幕保持常亮。
- **关于与更新。** 桌面版托盘有「关于 NanoLika」和「检查更新」；用 `pipx` 或 Docker 跑的运行时会在「设置 → 关于」里提示新版本（每六小时向 GitHub Releases 查一次，不下载任何东西，不上报任何信息；`server.update_check = false` 关闭）。窗口在上次关闭的位置打开。
- **底下的活。** 事件时间线在事件循环之外分批写入，coding agent 的接口在线程里探测命令行和目录，忙起来的运行时不会卡住。`nanomuse serve` 用一句话解释坏掉的 `config.toml` 或写不了的数据目录。网页 App 除对话外的每个页面都按需加载。中文界面里原本是原始文本或英文的卡片现在是中文。
- **文档。** [docs/android.md](../android.md) 描述的是你真正下载的那个 App，一个 arm64 APK，先登录，Hands、Reach、多设备、通话、coding agent，密钥放在哪、怎么构建和发布；早先 Python 线的页面都加了「设计记录」的说明。到处都写明默认形象是龙。
