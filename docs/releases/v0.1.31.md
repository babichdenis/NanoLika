# NanoLika 0.1.31 · Locks

🐉 **NanoLika `0.1.31` “Locks”** closes the twenty-seven points the audit after 0.1.30 left open. Nothing new to learn; a number of things that were loose are now tight, on the phone, the desktop, the web app, the relay and the showcase.

After 0.1.30 we went through the whole thing: the Sentinel and its approval cards, the hub between your devices, the runtime's HTTP and WebSocket surface, the Android app, the desktop, the Cloud relay, the public showcase, and wrote down every point we were not sure about rather than deciding it in passing. This version is those decisions, made and shipped. The biggest one is that the runtime's **access token no longer appears in any URL**: the WebSocket takes it in its first frame, inline pictures and screenshots open through short-lived signed links, and the pairing link carries it in the fragment, which a browser never sends anywhere. Around it: the device being remote-controlled agrees first; reading another device's files asks; *for this conversation* is the one middle scope on every side; Enter in a messenger is approved like a tap on *Send*; the coding CLIs run with a scrubbed environment; `confirmed` on the MCP bridge is a ticket only the desktop's own host can write. The relay reserves the allowance per request under way and caps how many run at once, limits how fast a socket may talk to the hub, and checks itself every ten minutes. The showcase wakes a kept Muse only for its owner, starts it with a key that lapses on its own, pins a visitor's own provider to the addresses it checked, and reaches Docker through a narrowed proxy.

## Highlights

- **No token in any URL.** The socket is opened bare and the token is its first frame (`{"kind": "auth", "token"}`, within ten seconds, or 4401); `/api/files/*` and the browser frames open through **signed links** the client computes from the token (`?exp=&sig=`, HMAC-SHA256 over the expiry and the path; good for the next six to twelve hours and for that one path: a logged link opens one picture for a while, nothing else); the pairing link is `http://host:port/#token=…`. The web app, the phone module and the showcase follow. `?token=` is still accepted this release and goes in the next; the retired Electron tray's *Open in browser*, which handed such a link to the system browser, is gone with the app it belonged to.
- **The device being controlled agrees first.** Another device of your account that wants to run, read or write something on this one over the hub (`shell`, `files`, `file.get`, `file.put`, `open`, `screen`, `coding.send`, `coding.stop`) is approved by the person *at* this device: *once* or *always for that device*, a `remote_control:<device id>` grant under Permissions, revocable there. On NanoLika Desktop the *Remote control* switch is off by default and means "each device asks here".
- **Approvals, the same on every side.** `device_files` and `device_get` ask now (they were *safe*); the runtime's *for this task* is *for this conversation*, like the phone's, as long as the chat the call came from exists, and per target on Android; the Harness card lost *Always allow* until a Permissions page can list and revoke such answers; `python_execute` without a sandbox is *sensitive*; a vault placeholder in a shell or Python command is refused rather than passed on as text.
- **Enter is a send.** In a messenger's message field, Enter (or the keyboard's send action) is approved one at a time as an outbound action, like a tap on *Send*; the app being a chat app, or the field's hint saying send or message, is what decides.
- **The coding CLIs and the MCP bridge.** Codex, Claude Code and Cursor get the shell tool's scrubbed environment plus their own variables (`OPENAI_*`/`CODEX_*`, `ANTHROPIC_*`/`CLAUDE_*`, `CURSOR_*`, the cloud credentials when `CLAUDE_CODE_USE_BEDROCK`/`_VERTEX` says so), not the runtime's keys. A call over `nanomuse mcp` with `confirmed: true` is honoured only when `confirmed` is the ticket NanoLika Desktop's plugin computed, with a secret shared per launch, after the person said yes on the card.
- **Android.** `WebAppActivity` is no longer exported; plain `http://` is allowed only for addresses on your own network (`10.x`, `172.16–31.x`, `192.168.x`, `.local`), checked at the provider URL field too; 繁體中文 says 你.
- **NanoLika Cloud (relay 0.13.0).** Each request is **reserved while it runs and settled when it is over** (a picture or a clip at its price, a chat at a typical turn's worth, a clip still being made held until the task is seen done) so requests started together cannot overshoot the allowance together; at most `MAX_IN_FLIGHT` (4) requests of one account run at once (`429 too_many_in_flight`). The hub allows a socket 60 frames and 8 MB a second (twice that in a burst), drops what is over with one `rate_limited` a second and closes a socket that keeps flooding (4008). `GET /v1/admin/health` answers with aggregates only and a systemd timer reads it every ten minutes (`selfcheck.sh`, journal and an optional `ALERT_URL`). `POST /v1/auth/session-key` issues a key that lapses on its own.
- **The showcase.** A kept Muse (NanoLika Web) that sleeps is woken only for a request that proves the account's token (bearer, first frame or signed link) and a browser with the address alone gets a small page that takes the token from the app's storage and asks for the wake, so a bookmark still works and a stranger starts nothing. The container runs on a **session key** (`WEB_KEY_TTL_S`, 30 days) and the gateway keeps no Cloud key any more. A visitor's own provider is **pinned** to the addresses it resolved to when checked (the name as SNI and `Host`, the certificate checked against it), so DNS rebinding cannot point it inside our network later. The gateway reaches Docker through **`docker-proxy`** (containers and a look at the networks, no exec, images, volumes or build) and holds no socket.
- **Also in this version.** NanoLika Desktop on Windows draws the system caption buttons over its frameless window; signing out returns to the welcome sheet; the web app's `postMessage` names its target; the connector fields in the web app say what they do with an address.

## Upgrade Notes

- **Android installs over 0.1.30 and keeps your data.** `NanoLika-0.1.31-arm64.apk` (Android 8.0+, arm64; versionCode 32) is signed with the same key as every version before it. Verify with `sha256sum -c NanoLika-0.1.31-arm64.apk.sha256`.
- **Pairing links changed shape: update both ends.** A phone or a browser from 0.1.31 on sends the token in the socket's first frame and reads it from `#token=`; a runtime from 0.1.31 on still accepts the old `?token=` form, so an older app keeps working against a new runtime, and a new app works against an old runtime only through the link it already stored: update the runtime first, then the apps. `?token=` is removed in the next version.
- **Approvals you had given *for this task* are gone with the run they belonged to**, as always; the new *for this conversation* answers live as long as the chat does.
- **Running a relay?** 0.13.0 adds `MAX_IN_FLIGHT` (4; 0 = off), the hub's frame and byte buckets (fixed), `GET /v1/admin/health`, `POST /v1/auth/session-key`, and an `expires_at` column on `api_keys` (migrated on start). `deploy.sh` installs the self-check timer; set `ALERT_URL` in `.env` to be told about problems.
- **Running the showcase?** `docker compose up -d` now also starts `docker-proxy`; the gateway no longer mounts `/var/run/docker.sock`. Kept Muses keep running; the Cloud keys the gateway had stored are wiped on first start, and each account's next sign-in starts its container with a session key. `WEB_KEY_TTL_S` (30 days) says how long such a key lives.
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. The checksums are beside every file.

🐉 **NanoLika `0.1.31`「Locks」**：把 0.1.30 之后那轮全面排查留下的 27 条待决项逐条定了、做了。没有要新学的东西；原来松的地方，现在紧了，手机、桌面、网页版、中继和展示站都在内。

0.1.30 之后我们把整个项目过了一遍，Sentinel 和它的审批卡、设备之间的 hub、运行时的 HTTP 与 WebSocket 接口、Android 应用、桌面端、Cloud 中继、公开的展示站，拿不准的点一条条记下来，不顺手拍板。这一版就是这些决定，做完并发出来。最大的一条是运行时的**访问令牌不再出现在任何网址里**：WebSocket 在第一帧里收令牌，内嵌的图片和截图走短时效的签名链接，配对链接把令牌放在片段里，浏览器从不把片段发给任何服务器。围绕它：被远程控制的设备先同意；读别的设备上的文件要问；「本次对话」成了各端统一的中档范围；在聊天应用里按 Enter 和点「发送」一样要审批；编程 CLI 只拿到清洗过的环境变量；MCP 桥接的 `confirmed` 必须是桌面端自己的宿主签的票。中继按请求预留额度、限制每个账号同时在飞的请求数、限制 hub 上每个连接的帧速率，并每十分钟自检一次。展示站只为主人唤醒留存的 Muse，用会自动过期的会话 key 启动容器，把访客自带的服务商地址钉在校验时解析到的地址上，并通过收窄的代理访问 Docker。

### 亮点

- **网址里不再有令牌。** 套接字空着打开，令牌是第一帧（`{"kind": "auth", "token"}`，十秒内，否则 4401）；`/api/files/*` 和浏览器截图帧走客户端用令牌算出的**签名链接**（`?exp=&sig=`，对过期时间和路径做 HMAC-SHA256；六到十二小时内有效、只对那一条路径有效，被记进日志的链接只能在一段时间内打开那一张图，别的什么都做不了）；配对链接是 `http://host:port/#token=…`。网页版、手机模块、展示站同步跟进。`?token=` 这一版仍接受，下一版去掉；已退役的 Electron 托盘里那个会把带令牌的链接交给系统浏览器的「在浏览器中打开」，随旧应用一起没了。
- **被控设备先同意。** 账号下另一台设备想通过 hub 在这台设备上运行、读或写什么（`shell`、`files`、`file.get`、`file.put`、`open`、`screen`、`coding.send`、`coding.stop`），先由*这台设备前的人*批准，「仅此一次」或「这台设备总是允许」，后者是「权限」里一条 `remote_control:<设备 id>` 的授权，随时可撤。NanoLika Desktop 上的「远程控制」开关默认关，关着的意思是「每台设备都在这里问」。
- **各端一致的审批。** `device_files` 和 `device_get` 现在会问（原来是「安全」级）；运行时的「本次任务」改为「本次对话」，和手机一致，聊天还在，授权就在，Android 上按目标分别记；Harness 的审批卡先去掉「总是允许」，等有能列出、能撤销的权限页再加回；没有沙箱的 `python_execute` 升为「敏感」级；shell 或 Python 命令里出现金库占位符会被拒绝，而不是原样传下去。
- **Enter 就是发送。** 在聊天应用的消息框里按 Enter（或键盘的发送动作），按对外动作逐次审批，和点「发送」一样；判断依据是所在应用是聊天类，或输入框的提示里有「发送 / 消息」。
- **编程 CLI 和 MCP 桥接。** Codex、Claude Code、Cursor 拿到的是 shell 工具那套清洗过的环境，再加上各自需要的变量（`OPENAI_*`/`CODEX_*`、`ANTHROPIC_*`/`CLAUDE_*`、`CURSOR_*`，以及 `CLAUDE_CODE_USE_BEDROCK`/`_VERTEX` 打开时的云凭据），拿不到运行时的 key。通过 `nanomuse mcp` 来的 `confirmed: true` 只在它是 NanoLika Desktop 插件用每次启动共享的密钥、在人点了「同意」之后算出来的票据时才算数。
- **Android。** `WebAppActivity` 不再导出；明文 `http://` 只对你自己网络里的地址放行（`10.x`、`172.16–31.x`、`192.168.x`、`.local`），服务商地址输入框也按这个校验；繁體中文改说「你」。
- **NanoLika Cloud（中继 0.13.0）。** 每个请求**运行时预留、结束时结算**（图片或短片按价格、对话按一轮的典型用量、还在生成的短片在任务确认完成前一直占着），同时发起的请求不能一起超支；一个账号同时最多 `MAX_IN_FLIGHT`（4）个请求在飞（`429 too_many_in_flight`）。hub 允许每个连接每秒 60 帧、8 MB（突发翻倍），超出的帧丢弃并每秒最多回一条 `rate_limited`，持续刷屏的连接关掉（4008）。`GET /v1/admin/health` 只回汇总数字，一个 systemd 定时器每十分钟读一次（`selfcheck.sh`，写入 journal，可选 `ALERT_URL`）。`POST /v1/auth/session-key` 签发会自动过期的 key。
- **展示站。** 睡着的留存 Muse（NanoLika Web）只在请求能证明持有账号令牌时才唤醒（Bearer、首帧或签名链接），只拿着地址来的浏览器会看到一个小页面，从应用自己的存储里取令牌再请求唤醒，所以书签照样能用、陌生人敲地址什么也启动不了。容器用**会话 key** 运行（`WEB_KEY_TTL_S`，30 天），网关不再保存任何 Cloud key。访客自带的服务商被**钉在**校验时解析到的地址上（域名只作 SNI 和 `Host`，证书照常校验），之后的 DNS rebinding 没法把它指进我们的内网。网关通过 **`docker-proxy`** 访问 Docker，只放行容器操作和查看网络，没有 exec、镜像、卷、构建，自己不再挂套接字。
- **这一版还有。** Windows 上的 NanoLika Desktop 在无边框窗口上画系统的标题栏按钮；退出登录回到欢迎页；网页版的 `postMessage` 指明目标；网页版里连接器的地址输入框写清它会拿这个地址做什么。

### 升级说明

- **Android 覆盖安装 0.1.30，数据保留。** `NanoLika-0.1.31-arm64.apk`（Android 8.0+，arm64；versionCode 32）和之前每个版本用同一把签名。校验：`sha256sum -c NanoLika-0.1.31-arm64.apk.sha256`。

- **桌面安装包没有经过公证。** macOS 第一次在「系统设置 → 隐私与安全性」里点「仍要打开」（或右键 → 「打开」），Windows 点「仍要运行」。每个文件旁边都有校验和。
