# NanoLika 0.1.24 · Signal

A phone number is a way in on every platform; the face moves on the web and the desktop; a computer joins by signing in and in no other way; a runtime that is slow to start says where it is; and the front door is plainer.

**Free, open source, non-profit: open source, built together: a personal agent for all.** Sign in with a phone number or an e-mail and the model comes with a free allowance, paid by the developer, the account page says how much is left and how it grows; when it is gone, bring your own key, with a step-by-step guide. Messages are not stored unless you choose to contribute them; nothing is sold; delete the account whenever you like. Report a bug, ask for a feature, send a pull request, every one brings a personal agent within everyone's reach. [Open an issue](https://github.com/nano-muse/nanoMuse/issues/new/choose) · [send a pull request](../../CONTRIBUTING.md) · [Discussions](https://github.com/nano-muse/nanoMuse/discussions) · [star the repo](https://github.com/nano-muse/nanoMuse).

## What changed

- **Sign in with a phone number** (relay 0.5.3). A mainland China mobile number works everywhere an e-mail did: the phone, the web and desktop app, nanomuse.cn/web: the six-digit code arrives by SMS, sent through Alibaba Cloud's 号码认证服务 with its ready-made signature and template (`CODE_SENDER=both`, `ALIYUN_SMS_API=dypns`; the older 短信服务 stays as `dysms`), and a password set under Account works for either. The identifier box switches to the number keypad when you start with a digit; on the phone the code box is marked as a one-time code, so Android offers the SMS it just received. Carrier one-tap login is not in: its SDK is closed, and this repository stays GPL with no closed component.
- **The face moves on the web and the desktop.** The dragon plays the four short clips the phone has (a head shake at rest, headphones and a laptop while working, a crystal ball while waiting, a star when pleased) in the chat header, the welcome, the sheet and onboarding; small sizes, lists, a system set to reduced motion and a clip that fails to load show the still. The avatar studio makes the same four clips for a new face once its stills are on, through the video model where the endpoint has one (the relay's `wan2.2-i2v-flash`, or Wan on Alibaba Cloud Model Studio) and the cost card counts them ("8 pictures and 4 clips"); a face from a provider without a video API keeps its stills.
- **The hub is the one way a computer joins.** The local-network host script and *Pair over the local network* are gone: install NanoLika Desktop, sign in with the same account, done, on any network. *Settings → Computers* on the phone lists the account's computers and says which account this phone uses, because a computer that is missing has nearly always signed in with another; a tap tells whether it answers. Coding agents and Devices say the same when no computer is there.
- **A signed-in runtime with no model key uses the relay.** A desktop or web runtime whose account was signed in but whose model still pointed at a provider with an empty key answered every message with a 401; at start-up the hub now makes the relay the model in that case, and leaves a local server alone.
- **When the runtime is slow to start, both sides say where they are.** The runtime starts its parts in named steps with time limits and logs each; `/api/health` says `starting: "<step>"` until it is done; the console is UTF-8 on Windows. The desktop shell probes health with Node's own HTTP client, writes the probe result, the port and who listens on it to `desktop-app.log` every ten seconds while it waits, and quotes them in the error box.
- **The Linux desktop runtime runs on older systems.** Built in a Debian 11 container (glibc 2.31), so Ubuntu 20.04 / 22.04 and their kin no longer stop with `GLIBC_2.35 not found`.
- **The hands are findable when they are off.** On a computer with the hands off, the agent's briefing names the switch (*Devices → Hands on this computer*), so "open the calendar app for me" gets the way to it; the Hands card tells Mac users about the Accessibility and Screen Recording permissions.
- **The front door, plainer.** Both READMEs open with one `IMPORTANT` callout: free, open source, non-profit; try it in the browser or download, with no amounts and no invitations; the entry notices in the apps and on the site say the same; GitHub is the default download source (the fastest from China too, in our measurements), the mirror the fallback. nanomuse.cn/web gains the password way in and says first that the browser version is for a first try: the phone app and the desktop app are the everyday ones, with the same account.
- **Long contributed conversations are kept whole** (relay 0.5.2). A turn over the size limit was cut mid-character and broke the operator's samples list and export; oversize turns are now cut by whole messages, and rows cut the old way still load.

## Install

| | |
|---|---|
| Browser | [nanomuse.cn/web](https://nanomuse.cn/web/): a phone number or an e-mail |
| Android 8.0+, arm64 | `NanoLika-0.1.24-arm64.apk`: same signing key, installs over 0.1.23 (versionCode 25); `sha256sum -c NanoLika-0.1.24-arm64.apk.sha256` |
| Windows 10+ | `NanoLika-Desktop-0.1.24-win-x64.exe` (the app) · `nanomuse-desktop-terminal-0.1.24-windows-x64-setup.exe` (terminal) |
| macOS 12+ | `NanoLika-Desktop-0.1.24-mac-arm64.zip` / `-mac-x64.zip` (unzip, drag to Applications) or the `.dmg` (the app) · `nanomuse-desktop-terminal-0.1.24-macos-arm64.pkg` / `-x64.pkg` (terminal) |
| Linux x64 | `NanoLika-Desktop-0.1.24-linux-x64.AppImage` / `.deb` (the app) · `nanomuse-desktop-terminal-0.1.24-linux-x64.deb` / `.tar.gz` (terminal) |

GitHub's own downloads are the fastest source from China too in our measurements; if they fail where you are, the same files are on [nanomuse.cn/dl/v0.1.24/](https://nanomuse.cn/dl/v0.1.24/) within fifteen minutes. The desktop installers are not notarised: on macOS open it once from System Settings → Privacy & Security → *Open Anyway* (or right-click → *Open*), on Windows click *Run anyway*. `SHA256SUMS-desktop-app.txt` and `SHA256SUMS-desktop-terminal.txt` list every checksum. The installers arrive a little after the APK: CI builds them from the tag.

### 变了什么

- **手机号登录**（中转 0.5.3）。中国大陆手机号在原来能用邮箱的每个地方都能登录，手机 App、网页和桌面版、nanomuse.cn/web：六位验证码通过阿里云号码认证服务发短信，用它自带的签名和模板（`CODE_SENDER=both`、`ALIYUN_SMS_API=dypns`；老的短信服务保留为 `dysms`）；在「账号」里设过密码的话，手机号或邮箱配密码都能登。输入框以数字开头就切成数字键盘；手机上验证码框标成一次性验证码，Android 会把刚收到的短信直接填进来。运营商一键登录没有做：它的 SDK 是闭源的，而这个仓库保持 GPL、没有闭源组件。
- **网页和桌面版的形象动起来了。** 小龙在对话页头、欢迎页、形象面板和引导页里播放手机上那四段短片，休息时晃晃头、工作时戴着耳机敲电脑、等你时玩水晶球、开心时抛星星；太小的地方、列表、系统开了「减少动态效果」、短片加载失败时，用静态图。形象工作室在新形象的静态图画好之后，也用视频模型做同样的四段短片，中转的 `wan2.2-i2v-flash`，或阿里云百炼上的万相，费用卡里一起算（「8 张图加 4 段短片」）；服务商没有视频接口的，就只有静态图。
- **电脑只有一种接入方式：登录。** 局域网脚本和「局域网配对」去掉了：装 NanoLika 桌面版，登同一个账号，就好了，任何网络都行。手机的「设置 → 电脑」列出这个账号下的电脑，并写明这台手机登的是哪个账号，电脑没出现，多半是登了另一个；点一下能看它是否在线。编程助手和设备页在没有电脑时也这么说。
- **登录了账号但没配模型 key 的运行时，自动用中转。** 桌面版或网页版登录了账号，但模型还指着一个 key 为空的服务商，每条消息都回 401；现在启动时 hub 会把中转设为模型，本地服务器（Ollama、LM Studio、局域网地址）不动。
- **运行时启动慢的时候，两边都说自己在哪。** 运行时分步启动、每步有时限并写日志；`/api/health` 在启动完成前会说 `starting: "<步骤>"`；Windows 上控制台用 UTF-8。桌面壳用 Node 自己的 HTTP 客户端探测健康，等待期间每十秒把探测结果、端口是否打开、谁在监听写进 `desktop-app.log`，并在报错框里引用。
- **Linux 桌面运行时能在老系统上跑。** 在 Debian 11 容器里构建（glibc 2.31），Ubuntu 20.04 / 22.04 之类不再报 `GLIBC_2.35 not found`。
- **Hands 关着的时候也找得到。** 电脑上 Hands 关着时，智能体的说明里会写明开关在哪（「设备 → 这台电脑的 Hands」），「帮我打开日历」会得到路径而不是「做不到」；Mac 用户会被告知需要「辅助功能」和「屏幕录制」权限。
- **门面更清爽。** 两份 README 开头只有一条 `IMPORTANT` 提示，免费、开源、非营利；在浏览器里试或下载，不写额度数字，不拉新；App 和官网的入口说明也一样；下载默认走 GitHub（实测国内也是最快的），镜像作为备用。nanomuse.cn/web 多了密码登录，并且先说清楚：浏览器版适合先试一试，天天用的是手机 App 和桌面版，同一个账号。
- **贡献的长对话完整保存**（中转 0.5.2）。超长的一轮以前会从字中间截断，把运营者的样本列表和导出弄成 500；现在按整条消息截，老数据也照常读。
