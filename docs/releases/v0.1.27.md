# NanoLika 0.1.27 · Ledger

🐉 **NanoLika `0.1.27` “Ledger”** puts one switch over what the relay keeps of your chats, lets a member pick any model under the Cloud key from a list instead of typing an id, gives the operator every line (who signed in from where, with which app, what each request was) and ships the DeepSeek Harness desktop as a preview.

The headline is **Data controls**. *Settings → Data controls* on every app holds one switch, *Help improve nanoMuse's AI models*. While it is on, the relay keeps the text of your chats with the Cloud models (what you wrote, what the model answered, the tool calls it chose) for the community's own open model; not your memory or SOUL, not what tools returned, not pictures or clips, and never next to who you are. The page counts the turns kept and deletes them with one tap. The co-creation programme, its name and its one-time ¥10 are gone; the starter ¥10 is as it was, and an invitation now credits both sides ¥5. [docs/privacy.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/privacy.md) and [nanomuse.cn/privacy](https://nanomuse.cn/privacy/) say all of it in one place, including what is new this version: the relay records the network address and the client software with every sign-in, request, event and device.

The other story is **the operator's page**. Every account's drawer reads to the first line (every request, every event, every sign-in and device with its address and client) an address opens the accounts seen from it, the kept conversations are listed in full and exportable per account, and the phone in the browser reports its visitors and each demo to the same page.

## Highlights

- **Data controls** (relay 0.9.0). One switch on the phone, the web and desktop apps, the dsh plugin and the console at `cloud.nanomuse.cn`; the page says how new accounts start on that relay (`IMPROVE_DEFAULT`), counts the turns kept, links the privacy policy and deletes everything kept. `/v1/me` carries it under `contribute`, and the timeline names every change.
- **An invitation credits both sides, and the co-creation bonus is gone.** Each new person who signs up with your code adds ¥5 to your allowance and ¥5 to theirs; the exhausted-allowance message, the heads-up, the account pages and the first-sign-in steps say so on every app.
- **A member picks from the models under the Cloud key; nothing to type** (relay 0.10.0). The relay reads the provider's own `/models` under the operator's key once an hour, sorts the ids into chat and picture models (spoken, heard, embedding and rerank models left out) and lists them in a member's `/v1/models` after the menu, each priced as the dearest menu model of its kind and marked when it reads pictures. Connections → Model on the web and the desktop shows one list in two groups, *Menu* and *More models on your account*; the picture and clip pickers get the same second group; the phone app and the dsh plugin read the relay's list already. A guest sees the menu alone.
- **The relay records where and with what, and the operator reads every line** (relay 0.10.0). Each sign-in, request, event and device carries the network address and the client software; the account keeps its first and last address, its last client and when it was last seen. The admin page: a *Client / IP* column (the search finds an address), the account's addresses with how often and from which platforms, the statement and the timeline paged to the first line, an address opening the accounts seen from it, a *By account* table under *Data controls* opening the kept conversations in full (every message, every tool call with its arguments) with an export of that one account's turns. The training export carries no address.
- **The phone in the browser keeps its visitors' whereabouts** (showcase gateway 0.3.0). A row per visitor with the first and latest address and browser, a row per demo with when, from where, with what, whether it brought its own key, what it used and why it ended; `GET /api/demo/admin` hands it to the relay's admin page as a fourth panel and into each account's drawer. The production showcase calls the relay on the shared Docker network so the visitor's address arrives as sent.
- **nanoMuse on DeepSeek Harness ships as a preview.** The bundle (the account as the *nanoMuse Cloud* provider, the Muse window, the first run, Hands over MCP and Reach both ways on [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)) comes packed with this release as `nanoMuse-Harness-0.1.27.tgz`, for people who run DeepSeek Harness Desktop 0.2.0-rc.2: start the app once, quit it, `dsh plugin --profile desktop add nanoMuse-Harness-0.1.27.tgz`, start it again ([harness/README.md](https://github.com/nano-muse/nanoMuse/blob/main/harness/README.md)). A preview next to the desktop app, not instead of it.
- **The macOS desktop build signs and notarizes itself once the Apple credentials exist.** `package-mac.sh` reads a Developer ID certificate and an App Store Connect key from the repository secrets, signs under the hardened runtime, notarizes and staples; until an Apple Developer account is behind the project the releases stay ad-hoc signed.
- **The three hosts promise HTTPS for a year** (`Strict-Transport-Security`), **one licence in every label** (`GPL-3.0-or-later` in the OCI labels and the manifests), **the desktop app on Electron 44** and **the web app on Vite 8** (`npm audit`: none on both).
- **The phone in the browser is drawn the way the Android app draws it** (lite mode follows the Android app screen by screen) and **its capsule no longer sticks on its last step**, the phone comes back to NanoLika when the hands are done, NanoLika is first in the dock and the sign-in fields stay above the keyboard.
- **The Android unit tests compile again** (`ReachTest` against the hub-only Reach; 73 tests pass), **the Android app reads optional JSON strings through one helper** (no more literal "null" in goals, check-ins and ideas), **the relay no longer logs a traceback when a client disconnects mid-request**, **Dependabot watches every package**, and **`CITATION.cff` names the current version**.

## Upgrade Notes

- **Android installs over 0.1.26 and keeps your data.** `NanoLika-0.1.27-arm64.apk` (Android 8.0+, arm64; versionCode 28) is signed with the same key as every version before it. Verify with `sha256sum -c NanoLika-0.1.27-arm64.apk.sha256`.
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. They arrive a little after the APK (CI builds them from the tag) and `SHA256SUMS-desktop-app.txt` / `SHA256SUMS-desktop-terminal.txt` list every checksum.
- **Data controls replace the co-creation programme.** The switch is on for accounts created on `cloud.nanomuse.cn` from relay 0.9 on and keeps what older accounts had chosen; the allowance never changes with it. Everything kept can be deleted on the page; only turning the switch off does not delete.
- **The relay now records network addresses and client software** with sign-ins, requests, events and devices, deleted with the account; [docs/privacy.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/privacy.md) says what and why. Running a relay? Behind Caddy the address is the first hop of `X-Forwarded-For`; `WEB_ADMIN_URL` / `WEB_ADMIN_TOKEN` connect the showcase's visitors to the admin page, `CLOUD_CATALOG=0` keeps the menu alone for members.
- **Running the showcase?** `SHOWCASE_ADMIN_TOKEN` opens `GET /api/demo/admin`; set `WEB_RELAY_URL` to the relay's internal name on the shared Docker network (`http://nanomuse-relay:8787`) so the visitor's address reaches the relay, through the public name Caddy replaces it. [demo/showcase/README.md](https://github.com/nano-muse/nanoMuse/blob/main/demo/showcase/README.md).
