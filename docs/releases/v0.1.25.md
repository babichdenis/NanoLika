# NanoLika 0.1.25 · Mirror

🐉 **NanoLika `0.1.25` “Mirror”** gives the account one name and one face on every device, puts a *Stop* button over the desktop while the hands work, and makes the desktop app start, or say why it does not.

The headline is **one agent, the same everywhere**. Rename it or draw it a new face on the phone and the desktop wears it a moment later, and the other way round; the look lives with the account, not with a device. The avatar studio on the web and the desktop now draws in the phone's seven styles, so a face described on either comes out alike.

The other story is **a desktop app you can trust to come up**. The runtime opens its port first and finishes starting behind it, the shell's error box names the cause when it still fails (a slow start, a `config.toml` that really does not parse, a Linux runtime refused for its glibc) and the macOS runtime verifies the relay's certificate with a bundle it actually has, so a computer is no longer “refused”. Everything is light by default, with *Appearance* to choose, and every screen says less.

## Highlights

- **One name and one face for the account** (relay 0.7.0). The agent's name and look (the dragon, an emoji on a colour, or a face drawn in the avatar studio with its five stills) live with the account (`GET` / `PUT /v1/me/profile`, last writer wins) and follow you to every device. The relay tells the devices on the hub, each fetches the new revision and wears it; the first device to sign in seeds an empty profile with what it has. Nothing else travels: keys, providers and settings stay where they were entered; the privacy note says what the relay now keeps.
- **A stop button on the desktop stage.** While the hands work the computer, the pill at the top of the screen has *Stop* (a click ends the run the way the shortcut does) and the stage lets clicks through everywhere else, so the desktop stays usable underneath.
- **Seven avatar styles on the web and the desktop** (3D toy (Muse's), flat, 3D clay, watercolour, pixel, line, sticker) the phone's list, with the same words to the model. *Settings → Draw a new one* shows the chips and starts the studio straight away.
- **Light by default.** The web and desktop app, nanomuse.cn/web's sign-in page, the relay's console and the site are light unless you choose otherwise; *Settings → Appearance* has *Light*, *Dark* and *Follow the system*, and the site's footer has a toggle.
- **The runtime opens its port first.** A slow step used to leave `/api/health` unreachable and the desktop app waiting for a port that never opened; the services now start in the background and `/api/health` says `starting: "<step>"` while they do. A watchdog writes where every thread is to the log at 20 s and 60 s. The desktop shell's error box tells the causes apart: a runtime that answered but never came up, a `config.toml` that really does not parse (that message used to be shown for every failure), a Linux runtime refused for its glibc, and `netstat` on Windows is read with a buffer large enough for machines with many sockets.
- **The relay's certificate is checked with a bundle the bundled runtime has.** The desktop runtime on macOS could not verify `cloud.nanomuse.cn`'s certificate and the Devices page said the account had turned this computer away. The runtime now points Python at certifi's bundle when the system has none to offer, and a certificate failure is reported as a disconnect with its reason.
- **The sign-in page fits a landscape window.** In the desktop app and a wide browser the words sit on the left and the form on the right; a phone keeps the single column. The form says less.
- **Your own key is a step after sign-up, and a row in Settings.** After a new account the web app asks the third question the phone asks: *Which model answers?*, and while the account's model answers, *Settings → Model* shows *Use my own API key*.
- **Pictures are queued, not refused** (relay 0.6.3). The image provider allows only a couple of pictures at once and answered the studio's four with `429`; the relay now draws through a gate and retries with growing pauses, the runtime's studio draws two at a time and waits a 429 out, and the card says *The image provider is busy right now: try again in a minute* when it still fails.
- **A number the SMS sender cannot reach is told so at once** (relay 0.6.1). Codes reach mainland China numbers only for now; elsewhere, sign in with an e-mail address, every sign-in form says so instead of promising a code that never comes.
- **Fewer words on every screen.** The Devices, Account, Connections and Settings screens of the web and desktop app, and the phone's welcome, Cloud, Devices, PC, Hands, coding and media pages, keep every control and lose the paragraphs around them.

## Upgrade Notes

- **Android installs over 0.1.24 and keeps your data.** `NanoLika-0.1.25-arm64.apk` (Android 8.0+, arm64; versionCode 26) is signed with the same key as every version before it. Verify with `sha256sum -c NanoLika-0.1.25-arm64.apk.sha256`.
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. They arrive a little after the APK (CI builds them from the tag) and `SHA256SUMS-desktop-app.txt` / `SHA256SUMS-desktop-terminal.txt` list every checksum.
- **Linux: 0.1.24 or newer only.** The Linux runtime is built in Debian 11 (glibc 2.31); the desktop shell now says so when an older build is refused.
- **Running your own relay?** 0.7.0 adds the account profile (`/v1/me/profile`, one row per account, created on start, nothing to migrate by hand) and 0.6.3's image gate (`IMAGE_CONCURRENCY`, `IMAGE_RETRIES`). [docs/cloud.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/cloud.md) has the settings.

🐉 **NanoLika `0.1.25`「Mirror」**：一个账号，在每台设备上都是同一个名字、同一张脸；操作电脑时屏幕上随时有「停止」；桌面版能打开了，打不开也会说清为什么。

这一版的主线是**一个智能体，到哪都一样**。在手机上改个名、画张新脸，桌面版片刻之后就换上，反过来也是；形象跟着账号走，而不是跟着某台设备。网页和桌面版的形象工作室现在有了手机上的七种画风，在哪台设备描述出来的脸都一样。

另一条线是**一个靠得住、能启动的桌面版**。运行时先开端口，再在后面启动其余部分；还是起不来时，壳的报错框会说清原因，启动慢、`config.toml` 真的解析不了、Linux 运行时因 glibc 太旧被拒绝；macOS 上的运行时用自己带的证书链验证中转，电脑不再被「拒绝」。所有界面默认浅色，「外观」里可以选，每个页面的字都少了。

### 亮点

- **一个账号，一个名字，一张脸**（中转 0.7.0）。智能体的名字和形象，小龙、彩色底上的 emoji，或在形象工作室里画出来的那张脸和它的五张静态图，存在账号里（`GET` / `PUT /v1/me/profile`，后写的生效），跟着你到每台设备。中转通知 hub 上的各台设备，各自取回新版本换上；第一台登录的设备会把自己的样子填进空的账号。别的都不走这条路，key、服务商和设置留在原来输入的地方；隐私说明里写了中转现在保存什么。
- **桌面 stage 上的「停止」。** Hands 操作电脑的时候，屏幕顶部的胶囊里有「停止」，点一下就和快捷键一样结束这一轮；其余地方点击都穿透，桌面照常能用。
- **网页和桌面版的七种画风**，3D 玩具（Muse 的那种）、扁平、3D 黏土、水彩、像素、线描、贴纸，和手机上同一份列表、同样的提示词。「设置 → 画一个新的」直接显示画风并开始。
- **默认浅色。** 网页和桌面版、nanomuse.cn/web 的登录页、中转控制台和官网都默认浅色，除非你自己选深色；「设置 → 外观」里有「浅色」「深色」「跟随系统」，官网页脚有切换。
- **运行时先开端口。** 以前某一步慢了，`/api/health` 就一直不通，桌面版等一个永远不开的端口；现在各项服务在后台启动，`/api/health` 期间会说 `starting: "<步骤>"`。20 秒和 60 秒后还没起来，看门狗会把每个线程在哪写进日志。桌面壳的报错框能分清几种情况，运行时有回应但没起来、`config.toml` 真的解析不了（以前每种失败都显示这句）、Linux 运行时因 glibc 太旧被拒绝，Windows 上读 `netstat` 的缓冲区也放大到了多连接机器够用的程度。
- **用运行时自带的证书链验证中转。** macOS 上的桌面运行时验证不了 `cloud.nanomuse.cn` 的证书，设备页却显示账号「拒绝」了这台电脑。现在系统没有证书链时运行时用 certifi 的那份，证书失败会按断开连接报告并写明原因。
- **登录页适配横屏窗口。** 桌面版和宽浏览器里文字在左、表单在右；手机还是单列。表单上的话也少了。
- **自己的 key：注册后的一步，设置里的一行。** 新账号之后网页版会问手机上问的第三个问题，「谁来回答？」，用账号自带的模型时，「设置 → 模型」里有「用我自己的 API key」。
- **生图排队，不再拒绝**（中转 0.6.3）。图像服务商一次只允许一个账号画两三张，工作室一次画四张就被回 `429`；现在中转通过一个闸门排队并逐步加长间隔重试，运行时的工作室一次画两张、遇到 429 等一等，还是不行时卡片上会写「图像服务商现在很忙，一分钟后再试」。
- **短信发不到的号码，马上告诉你**（中转 0.6.1）。验证码目前只支持中国大陆手机号，海外请用邮箱登录，每个登录表单都这么说，而不是承诺一条永远收不到的短信。
- **每个页面的字都少了。** 网页和桌面版的设备、账号、连接、设置页，手机上的欢迎、Cloud、设备、电脑、Hands、编程助手和媒体页，功能一个不少，周围的大段说明去掉了。
