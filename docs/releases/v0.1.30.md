# NanoLika 0.1.30 · Rooms

🐉 **NanoLika `0.1.30` “Rooms”** makes the desktop one app, built on DeepSeek Harness, and gives it the rest of the Muse desktop: the four rooms on the rail, the live stage, memory, the avatar studio and the remaining Settings pages.

0.1.28 and 0.1.29 shipped two desktops side by side: the older Electron app around the Python runtime, and *nanoMuse Harness*, the same agent on DeepSeek Harness, laid out like Muse. This version keeps one. **nanoMuse Desktop** is now the harness build: the installers carry the old name and the old application id, so they install over the app they replace, and a home left by nanoMuse Harness is taken over once, account and chats included. Inside, what was still missing against Muse's desktop is there. The rail has Muse's rooms: **Feed**, posts the agent writes for you from your instructions, your goals and the profile, with ♡ and *Discuss*; **Ideas**, suggestions in groups with *Start now*; **Goals**, Muse's categories, each goal a chat of its own with a one-line status, automations from the harness's schedule plugin and a timeline; **Library**, shelves of what it made for you, *+ Create…*, a viewer and a Markdown editor. While it works a screen (this computer's through Hands, a phone's through Reach) the **live stage** shows that screen picture-in-picture over the chat, with a caption of what it just did, its face where it last clicked, and *Take over*. It keeps **memory**: one-line facts about you, listed in the profile panel, with Muse's *Import memory* sheet for what another assistant knew. *Change look → Draw one* opens the **avatar studio**: four candidates in a 2×2 grid, pick one, the other poses are drawn from it, and the face is on every device. Settings → General has **App behavior** (open at login, the menu bar or tray icon, *Quick chat with ⌥ Space*) and Settings has **Connectors**, **File system access**, **Dictation**, **Permissions** and the local half of **Data controls**: import memory, download your agent data as a zip, reset. The hamburger's *Report a problem* takes a screenshot of the window first. On Android, the model you choose in Settings now reaches the chats already open. [docs/desktop-muse.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/desktop-muse.md) says, feature by feature, what is Muse's, what is ours and what is still missing.

## Highlights

- **One desktop app, on DeepSeek Harness.** `nanoMuse-Desktop-0.1.30-…` for Windows, macOS and Linux is the harness build with the bundle, dsh and the runtime for the hands inside; it installs over the old nanoMuse Desktop (same application id) and takes over a nanoMuse Harness home (`~/.nanomuse/harness` → `~/.nanomuse/desktop`) once. The Electron shell around the Python runtime (`desktop/app`) is retired; the terminal binary stays the zero-install fallback. For a DeepSeek Harness Desktop you already run, the bundle alone is `dsh-nanomuse-0.1.30.tgz`.
- **The four rooms.** Feed, Ideas, Goals and Library on the rail, each a `main` panel of the harness's layout, kept by one host service in `nanomuse/rooms.json` and streamed to the window. The agent writes the feed and the ideas in hidden chats, keeps each goal in a chat of its own (`goals_room_update`), and everything it delivers with `present` lands in the Library under `~/nanoMuse/Library`; `feed_post` and `library_add` from any chat. A dot on the rail for posts newer than your last visit.
- **The live stage.** The screen the agent is working on, picture-in-picture over the chat: the latest screenshot, dimmed while it works, a caption (*clicked "Save" · Finder*, *typed "hello" · WeChat*, *pressed ⌘ S · Pages*), the face as the cursor marker, ×, *Expand*, and *Take over* while a step runs. One frame kept in memory, taken from the hands' own results, dropped ten minutes after the last step.
- **Memory.** A `remember` tool for one-line facts you will expect it to know next time; every chat's prompt carries the list back. The profile panel's Memory tab lists, adds and forgets them, and *Import memory* takes what another assistant knew, one line per memory. Memory stays on this computer.
- **The avatar studio.** Describe the character, pick a style, see the cost against today's allowance, *Draw four*; the candidates arrive in a grid with *Option 1–4*; *This one* draws working, waiting, happy and oops from the pick with the runtime's own prompts, and the face is written to the account and worn everywhere. "Change your avatar to an orange cat with a scarf" in a chat opens the studio with the words (`draw_new_look`).
- **App behavior and the rest of Settings.** *Open at login*, *Show in the menu bar* / *system tray*, *Quick chat* (⌥ Space on macOS, Ctrl+Alt+Space elsewhere: the window comes up with a fresh chat; pressed while in front, it steps aside). *Connectors* lists the built-ins and the MCP servers behind the preset's tools with their tool lists; *File system access* the folders the agent uses, each opening in the file manager, and Full Disk Access on macOS; *Dictation* the harness's local voice input and the system's; *Permissions* what the agent may touch, where each switch is, and the recent approvals; *Data controls*: import memory, *Download your agent data* (a zip in Downloads, no sign-in token), *Reset*.
- **Report a problem, with a screenshot.** The hamburger's item saves a screenshot of the window to Downloads and opens the issue page with the build's facts filled in; a toast says which file to drag in.
- **Android: the Settings model reaches open chats.** A member who changed the Cloud group's model from the recommended one kept talking to the old model in the main chat, whose view-model lives as long as the app; now every open chat re-resolves on the spot, a chat pinned to a Cloud model follows the group once that model leaves it, and signing in again no longer adds a second *NanoLika Cloud* group.
- **Also in this version.** Hands approvals read the accessibility tree under the finger beside the model's label and the stricter class decides; the runtime's guard rails tightened (dynamic imports in the Python reach check, every redirect hop against the private-address guard, a scrubbed environment for MCP servers and remote shells); relay 0.12.0 caps wrong passwords per network address, refuses to send real codes without `CLOUD_SECRET`, and says a model provider's content refusal plainly (`400 content_rejected`); the Invite dialog's 404, focus kept inside the web app's sheets, and the other fixes in the [changelog](https://github.com/nano-muse/nanoMuse/blob/main/CHANGELOG.md).

## Upgrade Notes

- **Android installs over 0.1.29 and keeps your data.** `NanoLika-0.1.30-arm64.apk` (Android 8.0+, arm64; versionCode 31) is signed with the same key as every version before it. Verify with `sha256sum -c NanoLika-0.1.30-arm64.apk.sha256`.
- **NanoLika Desktop installs over the old NanoLika Desktop, and is a different app inside.** The installers carry the same application id, so Windows, macOS and Linux treat it as an update. The old app's chats, kept by the Python runtime under `~/.nanomuse`, are not read by the new one and stay where they are; the runtime still rides inside the new app for the hands. Sign in once with your phone number or e-mail; the account, the look, the devices and the allowance are the same.
- **nanoMuse Harness users keep everything.** The home under `~/.nanomuse/harness` is taken over into `~/.nanomuse/desktop` the first time the new app starts: the sign-in, the chats, the profile. The *nanoMuse Harness* installers are not built any more; install nanoMuse Desktop over it (it is the same build under the new name).
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. They arrive a little after the APK (CI builds them from the tag) and `SHA256SUMS-desktop.txt`, `SHA256SUMS-desktop-terminal.txt` and `SHA256SUMS-harness.txt` list every checksum.
- **Running a relay?** 0.12.0: `LOGIN_FAIL_PER_IP_HOUR` (default 30) caps wrong passwords from one address per hour; a relay that sends real codes refuses to start without `CLOUD_SECRET`, set it before updating; `400 content_rejected` is a new error code the apps already understand.

### 亮点

- **一个桌面端，建在 DeepSeek Harness 上。** Windows、macOS、Linux 的 `nanoMuse-Desktop-0.1.30-…` 就是 harness 版，里面带着插件包、dsh 和给 Hands 用的运行时；它覆盖安装旧的 nanoMuse Desktop（同一个应用 id），并把 nanoMuse Harness 的数据（`~/.nanomuse/harness` → `~/.nanomuse/desktop`）接管一次。包着 Python 运行时的 Electron 外壳（`desktop/app`）退役；终端版二进制仍是免安装的备选。已经在用 DeepSeek Harness Desktop 的，只装插件包：`dsh-nanomuse-0.1.30.tgz`。
- **四个房间。** 动态、点子、目标、构件在图标栏上，各是 harness 布局里的一个 `main` 面板，由宿主的一个服务存在 `nanomuse/rooms.json` 里并推送到窗口。智能体在隐藏的聊天里写动态和点子，每个目标放在它自己的聊天里（`goals_room_update`），用 `present` 交付的东西都进构件，存在 `~/nanoMuse/Library`；任何聊天里都可以 `feed_post`、`library_add`。有比你上次来更新的帖子时，图标栏上有一个点。
- **屏中屏。** 智能体正在操作的屏幕叠在聊天上方：最新一张截图，工作时压暗，一句说明（*点击了「保存」· 访达*、*输入了「hello」· 微信*、*按下 ⌘ S · Pages*），小脸标在光标处，×、「放大」，以及步骤进行中的「接管」。内存里只留一帧，取自 Hands 自己的结果，最后一步十分钟后丢弃。
- **记忆。** 一个 `remember` 工具，记你下次会指望它知道的一行事实；每个聊天的提示词都带着这份清单。个人面板的「记忆」标签可以看、添加、忘掉，「导入记忆」接收别的助手知道的东西，一行一条。记忆只留在这台电脑上。
- **换形象的画室。** 描述角色、选风格、看看要用掉今天多少额度，「画四个」；候选一格格排进网格，标着「选项 1–4」；「就这个」用运行时自己的提示词照着它画出工作、等待、开心、出错四个姿势，新形象写进账号、每台设备都戴上。在聊天里说「把形象换成戴围巾的橘猫」，它会带着这句话把画室打开（`draw_new_look`）。
- **应用行为和其余的设置。** 「开机启动」、「显示在菜单栏 / 系统托盘」、「快速唤起」（macOS 上 ⌥ Space，其他平台 Ctrl+Alt+Space，窗口带着一个新聊天出现；它已经在前面时再按，就让开）。「连接器」列出内置的和预设工具背后的 MCP 服务器及其工具清单；「文件访问」列出智能体用到的文件夹，每个都能在文件管理器里打开，macOS 上还有完全磁盘访问；「听写」是 harness 本地的语音输入和系统自带的听写；「权限」一页说清它能碰什么、每个开关在哪，附最近的审批；「数据控制」，导入记忆、「下载你的智能体数据」（Downloads 里的一个 zip，不含登录凭证）、「重置」。
- **带截图的问题反馈。** 菜单里的这一项先把窗口截图存到 Downloads，再打开填好构建信息的 issue 页面；一条提示告诉你拖哪个文件进去。
- **Android：设置里的模型用到已打开的聊天。** 成员把 Cloud 分组的模型从推荐模型换成别的之后，主要聊天里还在和旧模型说话，它的 view-model 和 App 活得一样久；现在每个打开的聊天当场重新解析，钉在某个 Cloud 模型上的聊天在那个模型离开分组后跟着分组走，重新登录也不会再多出一个 *NanoLika Cloud* 分组。
- **这一版还有。** Hands 的审批在模型给的标签旁边再读一遍手指下方的无障碍树，按更严的那一类判断；运行时的护栏收紧（Python 可达性检查认得动态导入，每一跳重定向都过一遍内网地址检查，MCP 服务器和远程 shell 拿到的是清理过的环境变量）；中继 0.12.0 按网络地址限制每小时的错误密码次数、没有 `CLOUD_SECRET` 就拒绝发真实验证码、把模型方的内容拦截直说出来（`400 content_rejected`）；邀请对话框的 404、网页应用弹层里的焦点保持，以及[更新日志](https://github.com/nano-muse/nanoMuse/blob/main/CHANGELOG.md)里的其他修复。

### 升级说明

- **Android 覆盖安装 0.1.29，数据保留。** `NanoLika-0.1.30-arm64.apk`（Android 8.0+，arm64；versionCode 31）和之前每个版本用同一把签名。校验：`sha256sum -c NanoLika-0.1.30-arm64.apk.sha256`。
- **NanoLika Desktop 覆盖安装旧的 NanoLika Desktop，但里面是另一个应用。** 安装包用同一个应用 id，所以 Windows、macOS、Linux 都把它当作更新。旧应用的聊天由 Python 运行时存在 `~/.nanomuse` 下，新应用不读，原地保留；运行时仍在新应用里给 Hands 用。用手机号或邮箱登录一次；账号、形象、设备、额度都是原来的。
- **nanoMuse Harness 的用户什么都不丢。** 新应用第一次启动时把 `~/.nanomuse/harness` 接管到 `~/.nanomuse/desktop`，登录、聊天、资料都在。*nanoMuse Harness* 的安装包不再构建；直接用 nanoMuse Desktop 覆盖装（换了名字的同一个构建）。
- **桌面安装包没有经过公证。** macOS 第一次在「系统设置 → 隐私与安全性」里点「仍要打开」（或右键 → 「打开」），Windows 点「仍要运行」。安装包比 APK 晚一点到（CI 从 tag 构建）；`SHA256SUMS-desktop.txt`、`SHA256SUMS-desktop-terminal.txt` 和 `SHA256SUMS-harness.txt` 列出全部校验值。
- **自己跑中继的话：** 0.12.0。`LOGIN_FAIL_PER_IP_HOUR`（默认 30）限制一个地址每小时的错误密码次数；发真实验证码的中继没有 `CLOUD_SECRET` 不会启动，升级前先设好；`400 content_rejected` 是新的错误码，各端 App 已经认识。
