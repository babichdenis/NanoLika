# NanoLika 0.1.28 · Harness

🐉 **NanoLika `0.1.28` “Harness”** turns the DeepSeek Harness desktop into an installer (NanoLika Harness for Windows, macOS and Linux, with the harness, the NanoLika bundle and the runtime for the hands inside) tells the operator where people are, checks a member's catalog models instead of guessing from their names, and fixes the model that did the work not being the one picked.

The headline is **nanoMuse Harness**. Until now the Muse on [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) was a tarball for people who already ran DeepSeek Harness Desktop. `nanoMuse-Harness-0.1.28-win-x64.exe`, `-mac-arm64.dmg` / `-mac-x64.dmg` and `-linux-x64.AppImage` / `.deb` are a desktop app of our own: the shell starts the harness's Host as a child process in Node mode with its own pinned Electron, keeps the profile under `~/.nanomuse/harness`, opens the harness's web app in a window with the three columns of Muse's Mac app (a rail, the chats, the conversation with the face above it) and brings the runtime along for Hands on this computer. Nothing is installed at first launch; no Node, pnpm or Python is needed. It is unsigned for now, and it is the desktop the project moves to: `docs/harness.md` says what phase 7 still owes.

The other story is **what the operator can see, and what a member actually gets**. The admin page names every address with its country, province and city from an offline copy of ip2region (nothing is asked of a third party) and shows the places behind the accounts, the sign-ins, the requests and the showcase's visitors. The relay asks each model under a member's key to prove what it can do (a one-word answer, then the colour of a small magenta square) instead of reading `vl` in a name; and the Android app binds the model you pick to the chat you picked it in, moves a Cloud pick to the front of the group so new chats follow, and chooses the Hands model in a stated order that starts with your choice: a member who picked `deepseek-v4.1-flash` is no longer billed for `qwen-vl-max`.

## Highlights

- **nanoMuse Harness: the desktop built on DeepSeek Harness, as installers.** `harness/desktop` is an Electron shell (Electron pinned to `44.0.0`, the version the harness's native loader accepts) that boots the harness with the `dsh-nanomuse` bundle in a profile of its own and opens its web app; the runtime for the hands is bundled on every platform; `~/.nanomuse/harness/desktop.log` says what happened. Windows (`.exe`), macOS (`.dmg` and `.zip`, Apple silicon and Intel), Linux (`.AppImage`, `.deb`); `SHA256SUMS-harness-desktop.txt` lists the checksums. The bundle `nanoMuse-Harness-0.1.28.tgz` still ships for DeepSeek Harness Desktop users. [harness/README.md](https://github.com/nano-muse/nanoMuse/blob/main/harness/README.md).
- **The admin page says where people are** (relay 0.11.0). Every address on the operator's page is named with its country, province and city from an offline [ip2region](https://github.com/lionsoul2014/ip2region) database the relay fetches once; a *Places* panel groups accounts, new accounts, sign-ins, requests and demo visitors by country and province, with a day range. No third party learns about a visitor; nothing more is stored.
- **The relay checks each catalog model instead of guessing from its name** (relay 0.11.0). Retired models leave the list, `vision` is what the model proved, `verified` marks a confirmed entry; a member's model menu on every app tells the truth about what can see.
- **A model picked in the Android app stays picked, and the hands use it.** The chat's pick is bound to that chat and moves a Cloud pick to the front of the group; Hands chooses its screen model in order (the Hands setting, the chat's model when it can see, the relay's sighted default, the vision group, the catalog last) and the picker says which model the hands will use.
- **A phone task survives a dropped connection, the capsule comes down with the run's last word, and the web app stops reconnecting to a session that has ended.** The operator waits up to 30 s for a phone to come back and goes on from the screen it then sends; the phone module ends the task's capsule on the chat run's final message and returns to NanoLika; the runtime web app reads the gateway's 4404 as *gone* instead of retrying every few seconds for hours.
- **A thinking level set in an app no longer makes the Cloud model refuse** (relay 0.11.0), **an upstream error is written down with the model and the provider's words**, and **the devices hub no longer logs a traceback when a device's socket closes**.
- **Natural Chinese where it still read like a translation**: the web app's dictionary, the Android app's strings, the Chinese README, the harness bundle and the site.

## Upgrade Notes

- **Android installs over 0.1.27 and keeps your data.** `NanoLika-0.1.28-arm64.apk` (Android 8.0+, arm64; versionCode 29) is signed with the same key as every version before it. Verify with `sha256sum -c NanoLika-0.1.28-arm64.apk.sha256`.
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. They arrive a little after the APK (CI builds them from the tag) and `SHA256SUMS-desktop-app.txt`, `SHA256SUMS-desktop-terminal.txt` and `SHA256SUMS-harness-desktop.txt` list every checksum.
- **nanoMuse Harness and nanoMuse Desktop are two apps.** The Desktop app (`nanoMuse-Desktop-…`) is the Python runtime with the web app; nanoMuse Harness (`nanoMuse-Harness-…`) is the same agent on DeepSeek Harness, the desktop the project moves to. They keep separate data (`~/.nanomuse` and `~/.nanomuse/harness`) and both sign in to the same account. On macOS the Hands' accessibility and screen-recording prompts are the system's own and come up on first use.
- **Running a relay?** 0.11.0 fetches `ip2region_v4.xdb` (11 MB) into its data directory after start (`CLOUD_GEOIP_DB` points at a copy you provide; `CLOUD_GEOIP=0` turns the lookup off) and probes catalog models in the background (`CLOUD_CATALOG_PROBE=0` goes by the names). Deploy with `cloud/deploy/nanomuse-hk/deploy.sh` as before.

### 亮点

- **nanoMuse Harness：建在 DeepSeek Harness 上的桌面端，做成安装包。** `harness/desktop` 是一个 Electron 外壳（Electron 锁定 `44.0.0`，harness 的原生加载器只认这个版本），用自己的 profile 带着 `dsh-nanomuse` 插件包启动 harness 并打开它的网页应用；每个平台都内置了「手」用的运行时；`~/.nanomuse/harness/desktop.log` 记录发生了什么。Windows（`.exe`）、macOS（`.dmg` 和 `.zip`，Apple 芯片与 Intel）、Linux（`.AppImage`、`.deb`）；`SHA256SUMS-harness-desktop.txt` 列出校验值。给 DeepSeek Harness Desktop 用户的 `nanoMuse-Harness-0.1.28.tgz` 照旧发布。[harness/README.md](https://github.com/nano-muse/nanoMuse/blob/main/harness/README.md)。
- **管理页能看出人在哪儿**（中继 0.11.0）。运营者页面上的每个地址都标出国家、省份和城市，来自中继启动后下载一次的离线 [ip2region](https://github.com/lionsoul2014/ip2region) 数据库；「地区」面板按国家和省份汇总账号、新账号、登录、请求和演示访客，可选时间范围。不会有第三方知道访客是谁，也不多存任何东西。
- **中继逐个验证 catalog 里的模型，不再按名字猜**（中继 0.11.0）。已下线的模型从列表里消失，`vision` 是模型证明过的能力，`verified` 标出验证过的条目；会员在每个 App 里看到的模型菜单，说的是实话。
- **Android App 里选的模型会一直是它，「手」也用它。** 对话里的选择绑定到这一个对话，Cloud 里选的模型移到组首；「手」按顺序选屏幕模型，「手」设置里指定的、你选的对话模型（能看图时）、中继的默认看图模型、看图模型组，最后才是 catalog，选择器会说明「手」将用哪个。
- **手机任务不再因为断线而失败，胶囊随对话的最后一句落下，网页应用不再向已结束的会话重连。** 操作器最多等 30 秒让手机重新连上，然后从它发来的屏幕继续；手机模块在对话跑完的最后一条消息上结束胶囊、回到 NanoLika；运行时的网页应用把网关的 4404 读作「已结束」，而不是几小时里每隔几秒重连一次。
- **在 App 里设置的思考程度不再让 Cloud 模型拒答**（中继 0.11.0），**上游错误会连同模型和服务商的原话一起记下**，**设备 hub 在设备断开时不再打印堆栈**。
- **把还像翻译腔的中文改自然**：网页应用的词典、Android App 的字符串、中文 README、harness 插件包和官网。
