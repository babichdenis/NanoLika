# NanoLika 0.1.32 · Union

🐉 **nanoMuse `0.1.32` “Union”** brings the four clients (the Android phone, the iPhone, nanoMuse Desktop and nanoMuse Web) to the union of what each of them could do. Whatever one had, the others have now: the whole account page, the catalogue of services to sign into, the agent's steps kept out of the chat unless asked for, a status line that says what it is on, and a star asked for at three moments. What stays platform-specific, and what is still open for a decision, is written down in [docs/parity.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/parity.md).

Since 0.1.31 the desktop had grown the fastest: laid out like the Muse desktop screen for screen, a catalogue of about seventy remote MCP servers to connect by signing in, a face that moves, a quick-chat key of your own, the first run as a recording of Muse shows it, while the phone had the account and the star asks the desktop lacked, and the iPhone had neither. This version evens that out. The phone gets the same seventy connectors, with the OAuth sign-in done on the phone and the token handed to the sandbox's MCP client; the desktop gets the account page the phone has had: the pool in yuan with the ways on when it runs low, the invite code, usage by kind and by model, the password, every device holding a key, the timeline, deletion; the iPhone gets all of that plus a password, an invite code and *Sign in to NanoLika Cloud: free* on its start screen; and the web app gets the switch for the agent's steps. Under all four, NanoLika Cloud 0.15 sets the allowance at runtime, so the figures the apps print are the relay's, nobody updates an app when the amounts change.

## Highlights

- **One account page, on every client.** Settings → Account on the desktop and NanoLika Cloud on the iPhone now have what the phone's page has: the allowance in yuan with the 80 % heads-up and, when it runs low, the ways on, your own key (→ Models, with the how-to), an invitation, and a star once; the invite code and link with what they earned; usage by kind (today / all time) and by model; the password: set, change, remove; every device holding a key, *Sign out* on each and *Sign out of every device*; the account's timeline; *Delete account*. The desktop reads it through its host's pass-through routes and keeps none of it on the computer. The iPhone also signs in with a password now (*Sign in with a password* / *Use a code instead*), takes a friend's invite code with the six digits, and prints the free amount above the form; so does the desktop's welcome.
- **Connectors on the phone.** *Settings → Connectors* on Android is the desktop's catalogue: Notion, Linear, Atlassian, Asana, GitHub, Sentry, Vercel, Cloudflare, Supabase, Stripe, PayPal, Figma, Canva, Dropbox, Box, Hugging Face, Context7 and the rest, about seventy, grouped as the desktop groups them with one line about each. Open servers add with a tap; a key service asks for the key; an OAuth service signs in with the account you already have: the phone discovers the server's authorization server, registers itself as a client, runs the PKCE flow in a Custom Tab and writes the token into the entry's `Authorization` header, which is how the sandbox's MCP client reads it; tokens about to lapse are refreshed when the app starts. A connected service is an MCP server entry under the catalogue id, so *Settings → MCP* shows it too. The catalogue is one file shared with the desktop (`scripts/connectors-json.mjs`).
- **The desktop in Muse's likeness.** The harness bundle (`dsh-nanomuse`) has the rail with the face as the agent's state (Chats · Search · Feed · Ideas · Goals · Library, a recent document, the hamburger), the chats column with the main and the side chats, the face and name over the conversation with a live status line and *Stop*, Muse's permission card over the harness's approvals, the live stage, the profile panel with memory, Settings as Muse's sheet in Muse's order (General with the account card, usage and theme swatches; Connectors; Computer use; File system access; Dictation; Wallet; Secure storage; Permissions; Message channels; Devices; Data controls; Help & support; Legal). *Connectors* is a catalogue (search, *Connected* and *Available*, a detail per connector) with the seventy remote servers to sign into and everything the agent can really reach (hands, mailbox, calendar, address book, your other devices, web, files, terminal, rooms, schedule, any MCP server). The dragon's four states are the phone's clips, looped silently wherever the face is drawn 44 px or larger; the quick-chat key is yours to change (⌥ Space on macOS, Ctrl+Alt+Space elsewhere); after signing in, three first-run pages ask for the computer, the files and the microphone, each skippable.
- **The steps out of the chat, the status in words.** On every client the agent's steps (tool pills, reasoning blocks, the Computer sheet on the phone, the floating step bar) are off by default and one switch away (Android *Settings → Appearance → Conversation*, Desktop *Settings → General → Conversation*, Web *Settings → Appearance*, iOS *Settings → Chat → Steps*). What stays is the line under the face, which names the work and never a state of mind: *nanoMuse is using Shell*, *Writing the reply*, *On it: 〈the request, briefly〉*; the iPhone's typing line reads *〈name〉 is on it*. No client says *Thinking…* any more. Fixed on the way: a finished tool step left the phone's Computer sheet stuck ([#67](https://github.com/nano-muse/nanoMuse/issues/67)).
- **A star, asked for at three moments.** When the free allowance is claimed (the account page after signing in), after the first task the agent finishes (a card on the phone and the web, the header line on the desktop: *First one done. Liked it?*), and when the allowance is used up (a third way on the card, next to the key and the invitation). Each is shown once where it happens; none comes back after *Star on GitHub*. The iPhone asks at the first and the third moment for now.
- **The amounts are the relay's: NanoLika Cloud 0.15.** `ALLOWANCE_CNY`, `INVITE_BONUS_CNY` and `SIGNUP_OPEN` are changed while the relay runs (*Settings › Runtime* on the operator's page or `POST /v1/admin/settings`) in force on the next request, and every client prints what `GET /v1/config` and the account sheet say (*¥10 of use to start*, *+¥5 for each of you*, the exhausted-allowance message) instead of a number baked into the app. Cloud 0.14 before it made the operator's page eleven views behind a side navigation, each a link.
- **iOS, on TestFlight.** The first iPhone build was archived, signed and uploaded by the *iOS · TestFlight* workflow (signed manually with the team's distribution certificate, made without a Mac) processed by App Store Connect and handed to the internal testers. With this version the iPhone has the whole account, the sign-in entry on the start screen, the steps toggle and the status line; the Muse shell (face, rooms, avatar studio, Reach) is the largest item on the open list.
- **Also in this version.** `nanomuse mcp` carries the runtime's connectors (mailbox, calendar, address book) into the desktop agent; a remote MCP server 250 ms away no longer *fails to fetch* from the harness (the dual-stack connect window is 1.5 s); the web app's status line, invite figures and the three star asks match the others.

## Upgrade Notes

- **Android installs over 0.1.31 and keeps your data.** `NanoLika-0.1.32-arm64.apk` (Android 8.0+, arm64; versionCode 33) is signed with the same key as every version before it. Verify with `sha256sum -c NanoLika-0.1.32-arm64.apk.sha256`.
- **Connectors on the phone are new.** Open and key services are plain MCP entries and behave as before. The OAuth sign-in follows the desktop's flow line by line but is in its first build on a device, if a service's sign-in does not complete, the entry is under *Settings → MCP* to retry or remove, and an issue with the service's name is the most useful thing to send. The token sits in the sandbox's `servers.json` next to API keys, as upstream keeps them.
- **The desktop's account page needs a relay that answers `/v1/me` with the pool** (NanoLika Cloud 0.15); against an older relay the tokens and the plan's bar are shown as before and the free amount falls back to ¥10 / ¥5.
- **Running a relay?** 0.15.0 adds the `settings` table (migrated at start), `GET /v1/config` (public), `POST /v1/admin/settings` and *Settings › Runtime* on the operator's page; 0.14.0 is the page in views. The environment's `ALLOWANCE_CNY` / `INVITE_BONUS_CNY` / `SIGNUP_OPEN` remain the defaults the runtime settings fall back to. The clients in this release work with 0.13 (fixed figures) but print the relay's amounts only from 0.15.
- **`?token=` stays one more version.** 0.1.31 said the query-string token would go in 0.1.32; the clients that would be cut off are still in use, so the runtime keeps accepting it (first-frame auth and `#token=` are the way; the query form lands in access logs) and the removal moves to the next version.
- **iOS is TestFlight-internal.** No public link yet; the maintainer's smoke test on a phone comes before Apple's beta review.
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. The checksum sits next to every file.

0.1.31 之后桌面端长得最快，照着 Muse 桌面逐屏排版、约七十个可登录接入的远程 MCP 服务目录、会动的表情、自己定的快捷唤起键、按录屏复刻的首次运行，而手机有桌面端缺的账号页和 star 提示，iPhone 两样都没有。这一版把它们拉平：手机拿到同样的七十个连接器，OAuth 登录在手机上完成、令牌交给沙箱里的 MCP 客户端；桌面端拿到手机早就有的账号页，以元计的额度和用完时的几条路、邀请码、按类型和模型的用量、密码、每台持有 key 的设备、时间线、注销；iPhone 拿到以上全部，再加密码登录、邀请码和开始页上的「登录 NanoLika Cloud，免费」；网页版拿到执行步骤的开关。四个端下面，NanoLika Cloud 0.15 在运行时设置额度，应用打印的数字都来自中继，改金额不用任何人更新应用。

### 亮点

- **一张账号页，每个端都有。** 桌面端的「设置 → 账号」和 iPhone 的 NanoLika Cloud 页现在和手机一样：以元计的额度、80 % 的提前提醒、额度不多时的几条路，自己的 key（→ 模型，带教程）、邀请、点一次 star；邀请码与链接以及它们带来的收益；按类型（今天 / 累计）和按模型的用量；密码，设置、修改、移除；每台持有 key 的设备，逐台「退出」或「所有设备退出」；账号时间线；「注销账号」。桌面端通过宿主的透传路由读取，电脑上不保存任何一项。iPhone 也能用密码登录了（「用密码登录」/「改用验证码」），能填朋友的邀请码，表单上方印着免费额度；桌面端的欢迎页同样。
- **手机上的连接器。** Android 的「设置 → 连接器」就是桌面端的目录，Notion、Linear、Atlassian、Asana、GitHub、Sentry、Vercel、Cloudflare、Supabase、Stripe、PayPal、Figma、Canva、Dropbox、Box、Hugging Face、Context7 等约七十个，按桌面端的分类分组，每个一句说明。开放服务一点即加；需要 key 的服务问你要 key；OAuth 服务用你已有的账号登录，手机发现服务的授权服务器、把自己注册为客户端、在 Custom Tab 里走 PKCE 流程，再把令牌写进条目的 `Authorization` 头，沙箱里的 MCP 客户端就是这样读到它的；快过期的令牌在应用启动时刷新。连接好的服务就是一条以目录 id 命名的 MCP 服务器条目，「设置 → MCP」里也能看到。目录是和桌面端共用的一个文件（`scripts/connectors-json.mjs`）。
- **桌面端照着 Muse 的样子。** Harness 插件包（`dsh-nanomuse`）有了以表情表示状态的侧栏（聊天 · 搜索 · 动态 · 想法 · 目标 · 资料库、最近文档、汉堡菜单）、主聊天与侧聊天的聊天列、钉在对话上方的表情与名字加实时状态行和「停止」、盖在 Harness 审批之上的 Muse 式权限卡、实时舞台、带记忆的资料面板，以及按 Muse 顺序排布的设置页（通用：账号卡、用量、主题色块；连接器；电脑使用；文件访问；听写；钱包；安全存储；权限；消息渠道；设备；数据控制；帮助与支持；法律）。「连接器」是一份目录，搜索、「已连接」与「可用」、每个连接器一页详情，包含七十个可登录的远程服务和智能体真正够得着的一切（手、邮箱、日历、通讯录、你的其他设备、网页、文件、终端、房间、日程、任何 MCP 服务器）。小龙的四种状态用手机端的短片，在 44 px 以上的任何位置静音循环；快捷唤起键可以自己改（macOS ⌥ Space，其他平台 Ctrl+Alt+Space）；登录后三页首次运行分别请求电脑、文件和麦克风，每页可跳过。
- **步骤出聊天，状态用人话。** 每个端上智能体的执行步骤（工具胶囊、推理块、手机上的 Computer 面板、浮动步骤条），默认关闭，一个开关可开（Android「设置 → 外观 → 对话」、桌面「设置 → 通用 → 对话」、网页「设置 → 外观」、iOS「设置 → 聊天 → 步骤」）。留下的是表情下面那一行，只说正在做的事、不说心理状态，「nanoMuse 正在使用 Shell」「正在写回复」「在做：〈简述请求〉」；iPhone 的输入提示行写「〈名字〉在做了」。没有一个端再说「思考中…」。顺手修了：已结束的工具步骤把手机的 Computer 面板卡住（[#67](https://github.com/nano-muse/nanoMuse/issues/67)）。

- **这一版还有。** `nanomuse mcp` 把运行时的连接器（邮箱、日历、通讯录）带进桌面智能体；250 ms 之外的远程 MCP 服务器不再在 Harness 里「fetch 失败」（双栈连接窗口改为 1.5 s）；网页版的状态行、邀请数字和三个 star 提示与其他端一致。

### 升级说明

- **Android 覆盖安装 0.1.31，数据保留。** `NanoLika-0.1.32-arm64.apk`（Android 8.0+，arm64；versionCode 33）和之前每个版本用同一把签名。校验：`sha256sum -c NanoLika-0.1.32-arm64.apk.sha256`。
- **手机上的连接器是新东西。** 开放服务和 key 服务就是普通的 MCP 条目，行为和以前一样。OAuth 登录逐行照着桌面端的流程，但这是第一次在真机上跑，如果某个服务登录没走完，条目在「设置 → MCP」里可以重试或删除，带着服务名提个 issue 是对我们最有用的。令牌放在沙箱的 `servers.json` 里，和上游保存 API key 的位置一样。
- **桌面端的账号页需要中继在 `/v1/me` 里返回额度池**（NanoLika Cloud 0.15）；对旧中继，仍显示 token 数和套餐进度条，免费额度回落到 ¥10 / ¥5。
- **自己跑中继的话：** 0.15.0 增加 `settings` 表（启动时自动迁移）、公开的 `GET /v1/config`、`POST /v1/admin/settings` 和运维页的「设置 › 运行时」；0.14.0 是分视图的运维页。环境变量 `ALLOWANCE_CNY` / `INVITE_BONUS_CNY` / `SIGNUP_OPEN` 仍是运行时设置清空后回落的默认值。这一版的客户端对 0.13 也能用（固定数字），但只有 0.15 起才打印中继的数字。
- **`?token=` 再留一版。** 0.1.31 说过查询串里的令牌会在 0.1.32 去掉；会被切断的客户端还在用，所以运行时继续接受（正道是首帧鉴权和 `#token=`，查询串形式会进访问日志），移除顺延到下一版。
- **iOS 目前是 TestFlight 内部测试。** 还没有公开链接；维护者在真机上过一遍之后才轮到 Apple 的 beta 审核。
- **桌面安装包没有经过公证。** macOS 第一次在「系统设置 → 隐私与安全性」里点「仍要打开」（或右键 → 「打开」），Windows 点「仍要运行」。每个文件旁边都有校验和。
