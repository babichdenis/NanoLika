# NanoLika 0.1.37 · Weave

🐉 **NanoLika `0.1.37` “Weave”** weaves the thread tight. 0.1.36 made your conversations travel between your devices; 0.1.37 makes them *one*: every device signed into the account shows the same main conversation and the same side chats, merged in time, backfilled all the way to the first conversation (the one where your Muse got its name) with each turn written elsewhere saying where it came from. Another device's main chat no longer turns up as a side chat here; a side chat started on the phone is the same chat on the desktop, continued under the same id. And the Muse's name goes with the thread: given on one device, it is worn on all, a desktop signing in no longer resets it to the default on the way.

The app wears its own mark where it speaks for itself: the splash is the blue N on its tile in a quiet ring with the wordmark and one status line (the ring stops and the error shows when the start fails), and the sign-in and permission pages open with the same mark rather than a face that is not yet anyone's. The agent's steps are shown by default on every client. Devices is a page of cards: this device first with what it can do, the others with when they were last seen.

Three things that got in the way are fixed. On Linux the launcher icon "did nothing" after the window was closed: the process was still there, hidden; it now quits when the window closes and a second launch opens the window again. On a Mac the app asks for Screen Recording and Accessibility at launch through the system's own dialogs, screenshots take one path, and a black frame comes back as a plain permission message rather than a black picture handed to the model. On an iPad the composer could vanish with the keyboard; it comes back.

## Highlights

- **One thread.** Every device shows the account's one main conversation and the same side chats. Turns from the other devices sit between this device's own in time order, each marked *From Pixel 8* (or whichever device wrote it); a message deleted on one device disappears on all; a chat deleted elsewhere is archived on the desktop (the harness forgets nothing). Signing in (or turning sync back on) pulls first and then sends the whole history, oldest first, so the first conversation is there on every device. The desktop keeps the other devices' turns beside its sessions (`sync-remote.json`) and briefs the model on what arrived meanwhile before its next step; a second desktop joining an account whose conversation is underway does not begin the first conversation again.
- **The Muse's name follows you.** Named on the phone, named on the desktop, the name is applied and pushed on every client. The bug behind "the avatar syncs but the name does not" is gone: a desktop sharing its connections wrote the whole (still default) profile before its first pull, which renamed the account's Muse back to *NanoLika* and took a drawn face off every device. Connections now go up alone.
- **The blue mark.** The splash (`loading.html`), the sign-in door, the code and password pages and the permissions page on the desktop, the web, Android and iOS carry the brand mark from `docs/brand.md`; the face arrives with the conversation. The dragon icon leaves the desktop package.
- **The agent's steps show by default** on the desktop (`nanomuse.prefs.showSteps`), the web (`nm.show_steps`), Android and iOS (`nanomuse.show_steps`); a stored *off* stays off.
- **Devices as cards.** This device first (glyph, name renamed in place, OS and version, the online dot, what it can do as chips, the hub and remote-control switches) then the others in a grid with *Online · just now* / *Last seen 2 h ago*, the `@name` hint and *Forget this device* behind the dots (desktop and web; Android says when an offline device was last seen).
- **Linux opens again from the icon.** With the menu bar off, closing the window quits the process (the glow and capsule overlay windows were keeping it alive); a second launch opens the window or focuses it and says which in the log. A `.tar.gz` sits next to the AppImage for machines without FUSE.
- **The Mac asks at launch.** Screen Recording and Accessibility are requested through the native TCC calls (`@computer-use/node-mac-permissions`, `@computer-use/mac-screen-capture-permissions`: the packages UI-TARS-desktop uses) and the settings pane opens when refused; the Permissions page reads the same status. When the desktop app's operator is there, screenshots go through it alone, no second path through mss or pyautogui, no second prompt, no second kind of error. A screenshot that comes back black returns a permission error with the Screen Recording text instead of a black picture. *Restart* runs through `app.quit()` so the host and the operator stop cleanly; Chromium's `ThumbnailCapturerMac` / ScreenCaptureKit picker features are off to dodge the known dropped-frame bug (electron#44504); `package-mac.sh` signs the native modules unpacked from the asar. `docs/tasks/mac-check-0.1.37.md` lists what still wants a Mac with the certificate.
- **iPad: the composer comes back.** The tool strip could end up on the tab bar with no composer under it and no way to the keyboard, the composer's UIKit host had been torn down and SwiftUI, with nothing in the subtree changed, never rebuilt it. A watchdog notices and rebuilds it (`NanoMuseComposerWatch.swift`).

## Upgrade Notes

- **Android installs over 0.1.36 and keeps your data.** `NanoLika-0.1.37-arm64.apk` (Android 8.0+, arm64; versionCode 38) is signed with the same key as every version before it. Verify with `sha256sum -c NanoLika-0.1.37-arm64.apk.sha256`.
- **If your Muse's name was reset by a desktop sign-in**, give it once more on any device; it stays this time.
- **The relay is unchanged** (Cloud 0.19.0, `/v1/sync/*`): a self-hosted relay from 0.1.36 serves 0.1.37 as it is.
- **The agent's steps are on now.** If you had turned them off in Settings → Appearance (General on the desktop), they stay off.
- **macOS: still untried on a Mac by the maintainer** (the build machine is Linux), the launch-time permission dialogs, the single screenshot path and the black-frame message are on the task sheet above; a report from a Mac decides what changes next.
- **iOS is on TestFlight.** A public link is being set up (it opens once Apple's beta review clears); until then, internal testers.
- **The desktop installers are not notarised yet** (the Developer ID certificate is in progress). On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. The checksum sits next to every file.

## Community

nanoMuse is open source and free. Sign in with a phone number or an e-mail and you get a starting allowance; the developer pays for it. The account page shows what is left and how to add more. When it is gone, use your own key: Alibaba Cloud Bailian in mainland China, OpenRouter elsewhere ([how](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)). With an account, the text of your conversations is kept on nanoMuse Cloud so that your devices show the same chats, one switch in Data controls turns it off and deletes it; nothing is sold ([privacy policy](https://nanomuse.cn/privacy/)); delete the account whenever you want.

🐉 **NanoLika `0.1.37`「Weave」**：把线织紧。0.1.36 让对话在设备之间传递，0.1.37 让它们成为*同一个*：登录同一账号的每台设备看到同一个主聊天、同一批旁聊，按时间合并，一直回填到最早那场对话（给 Muse 起名的那一场），别的设备写的每一轮都标着来自哪里。别的设备的主聊天不再在这里显示成旁聊；手机上开的旁聊在桌面端就是同一个聊天，在同一个 id 下继续。Muse 的名字也跟着这条线走：在一台设备上起的名字，所有设备都戴上，桌面端登录不会再半路把它重置成默认值。

应用在替自己说话的地方戴上了自己的标志：启动页是蓝色的 N 和它的底板，安静的圆环、字标、一行状态（启动失败时圆环停下、显示错误）；登录页和权限引导也以同一个标志开场，而不是一张还不属于任何人的脸。各端默认显示智能体的操作轨迹。设备页改成卡片：本机在最前，列出它能做什么；其他设备写着最后一次在线的时间。

挡路的三件事修了。Linux 上关掉窗口后再点图标「没反应」，进程其实还在，只是藏着；现在关窗即退出，再次启动会重新打开窗口。Mac 上，应用启动时就通过系统自己的对话框请求屏幕录制和辅助功能，截图只走一条路，拿到黑图时回一句明白的权限提示，而不是把黑图交给模型。iPad 上输入框可能随键盘一起消失；现在会回来。

### 亮点

- **一条线。** 每台设备显示账号里同一个主聊天和同一批旁聊。别的设备的轮次按时间插在本机的轮次之间，每条标着「来自 Pixel 8」（或写它的那台设备）；一台设备上删掉的消息所有设备都消失；别处删掉的聊天在桌面端归档（harness 什么都不忘）。登录（或重新打开同步），先拉取、再把全部历史从最早开始推送，所以第一场对话在每台设备上都有。桌面端把别的设备的轮次存在会话旁边（`sync-remote.json`），在模型下一步之前告诉它这期间发生了什么；第二台桌面加入一个对话已在进行的账号时，不会再开始一遍「第一场对话」。
- **Muse 的名字跟着你。** 手机上起的、桌面上起的，各端都应用并推送。「头像同步了名字没同步」背后的 bug 找到了：桌面端分享自己的连接时把整个（还是默认的），资料写了上去，赶在第一次拉取之前，于是账号的 Muse 被改回「NanoLika」，画好的形象也从每台设备上掉了。现在连接单独上传。
- **蓝色标志。** 桌面、网页、Android、iOS 的启动页（`loading.html`）、登录门、验证码和密码页、权限页都用 `docs/brand.md` 里的标志；形象随对话出现。奶龙图标从桌面安装包里撤了。
- **操作轨迹默认显示**：桌面（`nanomuse.prefs.showSteps`）、网页（`nm.show_steps`）、Android、iOS（`nanomuse.show_steps`）；之前手动关掉的保持关闭。
- **设备卡片。** 本机在最前（图标、原地改名、系统和版本、在线点、能做什么的标签、hub 和远程控制开关），其他设备排成网格，写着「在线 · 刚刚」/「最后在线 2 小时前」、`@名字` 提示，「忘记这台设备」收在点点菜单里（桌面和网页；Android 的离线设备写最后在线时间）。
- **Linux 从图标能再次打开。** 菜单栏关着时，关窗即退出进程（光晕和胶囊这两个悬浮窗之前让它活着）；再次启动会打开或聚焦窗口，并写进日志。AppImage 旁多了一个 `.tar.gz`，给没有 FUSE 的机器。
- **Mac 启动即申请。** 屏幕录制和辅助功能通过原生 TCC 调用申请（`@computer-use/node-mac-permissions`、`@computer-use/mac-screen-capture-permissions`，UI-TARS-desktop 用的那两个包），被拒时打开设置面板；权限页读同一个状态。桌面应用的操作器在场时截图只走它，不再退到 mss 或 pyautogui，没有第二次弹窗、第二种报错。截回来的黑图变成带屏幕录制文案的权限错误，而不是一张黑图。「重启」走 `app.quit()`，host 和操作器干净地停下；关掉 Chromium 的 `ThumbnailCapturerMac` / ScreenCaptureKit 选择器特性，绕开已知的丢帧问题（electron#44504）；`package-mac.sh` 也给从 asar 解包的原生模块签名。`docs/tasks/mac-check-0.1.37.md` 列着还需要一台有证书的 Mac 来验证的事。
- **iPad：输入框回来了。** 工具条可能停在 Tab 栏上、下面没有输入框、也唤不出键盘，输入框的 UIKit 宿主被拆掉了，而 SwiftUI 在子树没有变化时从不重建它。一个看护者发现并重建（`NanoMuseComposerWatch.swift`）。
