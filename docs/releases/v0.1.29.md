# NanoLika 0.1.29 · Likeness

🐉 **NanoLika `0.1.29` “Likeness”** lays NanoLika Harness out like the Muse desktop, screen for screen (the first run, the window, the cards, the settings) and makes the macOS installers package again.

The 0.1.28 installers put the agent on DeepSeek Harness in a window of its own; what was inside the window was still, in most places, the harness's own web app with a nanoMuse sidebar. This version takes Muse's desktop as the measure, from the moment the app opens for the first time. The first run is full-window and follows Muse's sheets: a welcome with one *Sign in* pill, *Sign in or create an account* with a phone number or an e-mail, six code boxes that verify themselves (or a password), a spinner, then the permissions one card at a time: *Allow nanoMuse to use your computer?* on macOS, where *Allow* asks the system for Accessibility and Screen recording and turns into a check once granted; *Allow nanoMuse to access your files?* with the workspace folder and a native picker; *Your other devices*, and *ready*. The window has Muse's three columns: a rail in Muse's order with a dot on Chats while the agent works and the hamburger at the foot; a chats column with *Search*, **Main chat** and **Side chats** with *+*, pin, inline rename, archive and *Make main chat*; the face and name pinned at the top centre of the conversation with a status chip that tints while it works or waits, *Stop* beside it and *Invite* at the top right; your messages in accent-toned bubbles and the agent's in grey, timestamps and actions on hover; the composer as one pill docked at the bottom; the harness's approval card restyled into Muse's permission card. The face opens a profile panel beside the chat (the avatar with a pen, the name, the connection, and Activity, Approvals, Schedule and Memory) and Settings has Muse's pages: General, Account, Models, Agents, Computer use, Devices, Data controls, Help & support, Legal, Advanced, Sign out. On macOS the window has no title bar; the traffic lights sit over the rail, and the window's base colour follows the theme so nothing flashes white in the dark. [docs/desktop-muse.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/desktop-muse.md) says, feature by feature, what is Muse's, what is ours and what is still missing.

## Highlights

- **A first run like Muse's.** Full-window; welcome → sign in with a phone number or an e-mail → the code (or a password, `/v1/auth/login`) → the permissions carousel with ‹ › → ready. On macOS *Allow* on the computer card asks the system for Accessibility and Screen recording through the desktop shell; the files card opens a native folder picker; the devices card explains Reach.
- **The window, screen for screen.** Rail (Chats · Search · Devices · Schedules when installed · the hamburger), the chats column (*Search*, **Main chat**, **Side chats** with *+*; pin, rename, archive, *Make main chat* on each row), the conversation with the face and name pinned above it, a status chip, *Stop* and *Invite* (the account's code and link, from `/v1/me/invite`), accent and grey bubbles, the pill composer with no greeting over an empty chat.
- **Muse's permission card.** The harness's approval card restyled (shield, headline, *Allow once* in blue, *Reject*) and every answer recorded in the profile panel's Approvals tab.
- **A profile panel beside the chat.** The avatar with a pen (*Change look*, written to the account and worn on every device; *Edit name*), the connection, and four tabs: Activity, Approvals, Schedule, Memory.
- **Settings with Muse's pages.** General (with *Show DeepSeek Harness controls* under Developer, which brings the model picker, the modes and the workspace browser back), Account, Models, Agents, **Computer use** (the macOS permissions with *Open System Settings*, *Keep the screen awake while it works*), Devices, **Data controls**, **Help & support**, **Legal**, Advanced, Sign out.
- **No title bar on macOS.** The shell's window is title-bar-less with the traffic lights over the rail, drag handles where Muse has them, and a base colour that follows the theme.
- **The macOS builds of NanoLika Harness package again.** electron-builder names the bundle after `executableName`, which the packaging script did not look for; it now takes the bundle electron-builder left and renames it to the product's name before signing, so the zip and the dmg carry `NanoLika Harness.app`. Both this and the bundle's shell test under `/private/var` were found by the first macOS run of the workflow.

## Upgrade Notes

- **Android installs over 0.1.28 and keeps your data.** `NanoLika-0.1.29-arm64.apk` (Android 8.0+, arm64; versionCode 30) is signed with the same key as every version before it. Nothing in the phone app changed in this version beyond its number; it ships so that every platform carries the same version. Verify with `sha256sum -c NanoLika-0.1.29-arm64.apk.sha256`.
- **nanoMuse Harness keeps your data and your sign-in.** The profile under `~/.nanomuse/harness` is read by the new version; the first run shows once, and only when the app has never signed in on this machine.
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. They arrive a little after the APK (CI builds them from the tag) and `SHA256SUMS-desktop-app.txt`, `SHA256SUMS-desktop-terminal.txt` and `SHA256SUMS-harness-desktop.txt` list every checksum.
- **nanoMuse Harness and nanoMuse Desktop are two apps.** The Desktop app (`nanoMuse-Desktop-…`) is the Python runtime with the web app; nanoMuse Harness (`nanoMuse-Harness-…`) is the same agent on DeepSeek Harness, the desktop the project moves to. They keep separate data (`~/.nanomuse` and `~/.nanomuse/harness`) and both sign in to the same account.
- **Running a relay?** Nothing changed; 0.11.0 stays.

## Community

**Free, open source, non-profit: open source, built together: a personal agent for all.** Sign in with a phone number or an e-mail and the model comes with a free allowance, paid by the developer, the account page says how much is left and how it grows; when it is gone, bring your own key, with a step-by-step guide. What the servers keep is in the [privacy policy](https://nanomuse.cn/privacy/) and *Settings → Data controls* is yours; nothing is sold; delete the account whenever you like.

This is a preview, and the people building it use it every day; what breaks for you, and what you wish it did, is the most useful thing you can send. What we are after is bigger than one app (a personal agent that belongs to the person who runs it, built in the open on infrastructure anyone can reuse) and we look forward to finding out how far it goes with users and developers everywhere. Thank you to everyone who tried a build, reported what broke and asked for what was missing, every issue, idea and pull request brings a personal agent within everyone's reach. ### 亮点

- **像 Muse 一样的首次启动。** 整窗；欢迎 → 手机号或邮箱登录 → 验证码（或密码，`/v1/auth/login`）→ 带 ‹ › 的权限轮播 → 就绪。macOS 上电脑卡片的「允许」通过桌面外壳向系统申请辅助功能和屏幕录制；文件卡片打开系统的文件夹选择器；设备卡片说明 Reach。
- **窗口一屏一屏对照。** 图标栏（聊天 · 搜索 · 设备 · 装了插件时的日程 · 菜单）、会话列表（「搜索」、**主要聊天**、带「+」的**旁聊**；每行可置顶、改名、归档、「设为主要聊天」）、钉着形象和名字的对话、状态标签、「停止」和「邀请」（账号的邀请码和链接，来自 `/v1/me/invite`）、强调色和灰色气泡、空对话上方没有问候语的胶囊输入框。
- **Muse 式的权限卡。** harness 的审批卡改成盾牌、标题、蓝色的「允许一次」、「拒绝」，每一次回答都记进个人面板的「审核记录」。
- **聊天旁边的个人面板。** 带画笔的头像（「换个形象」写进账号、每台设备都用它；「改名」）、连接状态，以及活动、审核记录、日程、记忆四个标签。
- **按 Muse 分页的设置。** 通用（「开发者」下有「显示 DeepSeek Harness 控件」，打开后模型选择、模式和工作区浏览器回来）、账户、模型、智能体、**电脑操作**（macOS 权限加「打开系统设置」、「工作时保持屏幕常亮」）、设备、**数据控制**、**帮助与支持**、**法律信息**、高级、退出。
- **macOS 上没有标题栏。** 外壳窗口去掉标题栏，三个按钮落在图标栏上，可拖动的区域和 Muse 一样，底色跟随主题。
- **NanoLika Harness 的 macOS 版重新能打包。** electron-builder 按 `executableName` 给 bundle 起名，打包脚本没去找这个名字；现在它拿 electron-builder 留下的 bundle、签名前改成产品名，所以 zip 和 dmg 里是 `NanoLika Harness.app`。这个问题和插件包在 `/private/var` 下的 shell 测试，都是工作流第一次在 macOS 上跑出来的。

### 升级说明

- **Android 覆盖安装 0.1.28，数据保留。** `NanoLika-0.1.29-arm64.apk`（Android 8.0+，arm64；versionCode 30）和之前每个版本用同一把签名。这一版手机 App 除了版本号没有变化，发它是为了各平台版本号一致。校验：`sha256sum -c NanoLika-0.1.29-arm64.apk.sha256`。
- **nanoMuse Harness 的数据和登录都保留。** 新版本读 `~/.nanomuse/harness` 下原来的 profile；首次启动页只出现一次，而且只在这台机器从没登录过时出现。
- **桌面安装包没有经过公证。** macOS 第一次在「系统设置 → 隐私与安全性」里点「仍要打开」（或右键 → 「打开」），Windows 点「仍要运行」。安装包比 APK 晚一点到（CI 从 tag 构建）；`SHA256SUMS-desktop-app.txt`、`SHA256SUMS-desktop-terminal.txt` 和 `SHA256SUMS-harness-desktop.txt` 列出全部校验值。
- **nanoMuse Harness 和 nanoMuse Desktop 是两个应用。** Desktop（`nanoMuse-Desktop-…`）是 Python 运行时加网页应用；nanoMuse Harness（`nanoMuse-Harness-…`）是同一个智能体跑在 DeepSeek Harness 上，是项目接下来的桌面端。两者数据分开（`~/.nanomuse` 与 `~/.nanomuse/harness`），登录的是同一个账号。
- **自己跑中继的话：** 没有变化，仍是 0.11.0。
