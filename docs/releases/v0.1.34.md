# NanoLika 0.1.34 · Turns

🐉 **NanoLika `0.1.34` “Turns”** is about whose turn it is. When the hands reach a login, a code, a payment or a CAPTCHA, the agent hands over and *waits*, on the phone since 0.1.33, now on the desktop and in the browser too, and you say *Done* where you are: on the live stage, on the capsule, in the browser viewer, in the chat. The same places answer *Allow once / Deny* for an approval, so a running task no longer sends you back into the app. And your NanoLika can now answer in 飞书, 钉钉, 企业微信 and Telegram.

The other story is parity. The iPhone and the desktop get what the Android phone had: the face opens the agent page, *change your look to …* is caught in the chat with four candidates, Goals, Feed and Ideas are real rooms (the iPhone has a scheduler now), the first run is the same four pages. Under all of it, two model settings (`deepseek-v4.1-flash` for the chat, `qwen3.8-27b` for the hands) and the account knows where you are, so when the allowance is spent a mainland account is pointed to Alibaba Cloud Bailian and everyone else to OpenRouter. The connections you signed into on one device show on the others, without a credential ever leaving the device that holds it. What is still open is in [docs/parity.md](https://github.com/nano-muse/nanoMuse/blob/main/docs/parity.md).

## Highlights

- **Holds: the hands are handed over, and wait.** A *hold* belongs to one chat and one kind of hands: the browser, this computer, the phone. The agent opens one with the new `hand_over` action (a reason is required: *sign in*, *the code from your SMS*, *confirm the payment*), you open one with *Take over*, and *Done* closes it; while it is on, every action of that tool waits instead of failing, and the agent goes on from the page as you left it, told never to redo your work or type credentials. One `hold` event, one card everywhere: the desktop's stage (*Your turn* with *Done*, *I'll take it*), the web's browser viewer, the phone's capsule, the chat.
- **Approvals where you are.** The desktop's live stage carries **Allow once / Always in <app> / Deny** (always = a per-application grant, revocable on the agent page); a small always-on-top capsule shows the same card when the main window is behind the app being driven; the showcase phone's capsule answers **Allow once / Deny** on the spot. Only questions still open the app.
- **A browser you can drive (web).** The viewer takes over, clicks, types, scrolls, opens a URL, goes back, says *paused, waiting for you* while the agent waits, and *Done* hands it back.
- **Hands that do not fight you (macOS).** The hands can work in one application's window while you keep the mouse (the window is captured, the events go to its process) and each application asks once: *Let <Muse> use <App>?* (`[hands] mode = auto | screen | window`). Around the screen a transparent, click-through glow with the face at the pointer, amber while a hold is on; every overlay, and the window itself, is kept out of the screenshots. Written against the Quartz APIs and not yet tried on a Mac by the maintainer: see Upgrade Notes.
- **Chat apps.** 飞书, 钉钉, 企业微信 and Telegram over the vendors' long connections, no public address needed, after nanobot's design. One conversation per chat, replies streamed in place where the vendor allows editing, approvals answered with 允许 / 拒绝 or a button, files both ways. The first message from a stranger gets a six-character pairing code to approve in the app or with `nanomuse channels approve`; allowlists, group policy, *deliver here* chats for background results. *Settings → Chat apps* in the web app and the desktop; `nanomuse channels login feishu` creates the bot from a QR code. Optional extras `nanomuse[channels]`; the Docker image has them.
- **Two model settings.** With a NanoLika Cloud account the chat opens on **DeepSeek V4.1 Flash** (reads pictures, thinks before it answers) and the hands see the screen with **Qwen 3.8 27B**; the relay's menu says which model is for which lane, and every client reads that before its own defaults. Your own key fills both: Bailian or OpenRouter.
- **Where you are decides the way on.** The account carries a `region`; sign-in, onboarding, the allowance card, the account page and the presets put Alibaba Cloud Bailian first for a mainland account and OpenRouter first elsewhere, with one line that says why (Bailian only signs up accounts from mainland China). OpenRouter joined the own-key presets on every client, with its OAuth sign-in on the phones.
- **Connections travel with the account.** The remote MCP servers one device connected go into the profile: a name, an address, how it signs in; never a key (and the other devices list them as *Connected on <device>: sign in here to use it on this device*), with the sign-in prefilled.
- **The iPhone catches up.** The face opens the agent page (Activity, Approvals, Daily, Soul & memory, share sheet); *change your avatar to …* is caught in the chat with four candidates and a pick by words; Goals, Feed and Ideas are real rooms with a scheduler (foreground catch-up, a background refresh task, a local notification at the set time: *Check-in: <goal>, open to run it*); the four-page first run; a NanoLika settings page; coding agents over the hub; the iPad runs the Muse shell too; 249 strings in three languages.
- **The desktop catches up.** The face opens the agent page; the phone's avatar flow word for word, with the same memory line; Goals, Feed and Ideas on the phone's fence protocol with the phone's own idea list (byte for byte, with a test); guided macOS permissions in order; **a real version line and update check**: *nanoMuse Desktop <app> · harness <bundle>* in About and Help, a daily check against GitHub's releases with `nanomuse.cn/dl/index.json` as the fallback, a dot on the ••• menu and an *Update to 0.1.x* entry when there is one.
- **Plainer words, everywhere.** The community notice is *Free, open source, non-profit* and says who pays and what is kept; the star asks say what a star does; 你, not 您; no exclamation marks; the README and its nine translations in the same voice.
- **Three runtime fixes.** Adding a remote MCP server that is down gave a 500 and *Attempted to exit cancel scope in a different task* (now a 502 with the real cause, SSE tried after streamable HTTP); a message typed during a background pass was filed as that pass's work and left the chat for the Feed; unknown `/api/*` paths answered the app's HTML with a 200 (a 404 in JSON now).

## Upgrade Notes

- **Android installs over 0.1.33 and keeps your data.** `NanoLika-0.1.34-arm64.apk` (Android 8.0+, arm64; versionCode 35) is signed with the same key as every version before it. Verify with `sha256sum -c NanoLika-0.1.34-arm64.apk.sha256`.
- **The chat model changes for Cloud accounts.** The chat opens on `deepseek-v4.1-flash` (¥2 / ¥8 per million tokens at 0.7× against your allowance; it reads pictures and thinks before it answers). A model you picked yourself is kept. The hands keep `qwen3.8-27b`.
- **macOS window mode is untried on a Mac** by the maintainer (the build machine is Linux): the capture, the posted events, the Retina mapping and the per-application ask follow Apple's documented APIs and the Codex app's behaviour, but the first reports from a Mac decide whether `auto` stays the default. `[hands] mode = screen` is the 0.1.33 behaviour.
- **Chat apps need a bot of your own** at the vendor (飞书开放平台, 钉钉开放平台, 企业微信智能机器人, @BotFather); the settings screen lists the steps and the console link. No vendor was connected end to end from the build machine (the SDK calls were checked against the real packages offline) so the first report of a chat that does not answer, with its vendor, is the most useful thing to send. Android and iOS do not have the settings screen yet; set a chat app up in the web app or the desktop.
- **Running a relay?** Cloud 0.17.0: `/v1/models` entries carry `nanomuse.for` and `nanomuse.recommended_for`, `/v1/me` carries `region` and `spend.ways`, the profile carries `connectors` (the database migrates itself), `OPENROUTER_URL` is new and optional, and `CLOUD_MODELS` takes `for` / `recommended_for`. Older clients ignore all of it.
- **iOS is TestFlight-internal.** The Muse shell is on the iPhone and the iPad now. A routine runs in the background only when iOS gives the refresh task a slot; at the set time the phone reminds you to open it.
- **The desktop installers are not notarised.** On macOS open the app once from *System Settings → Privacy & Security → Open Anyway* (or right-click → *Open*); on Windows click *Run anyway*. The checksum sits next to every file.

## Community

nanoMuse is open source and free. Sign in with a phone number or an e-mail and you get a starting allowance; the developer pays for it. The account page shows what is left and how to add more. When it is gone, use your own key: Alibaba Cloud Bailian in mainland China, OpenRouter elsewhere ([how](https://github.com/nano-muse/nanoMuse/blob/main/docs/own-key.md)). Messages are not stored by default and nothing is sold ([privacy policy](https://nanomuse.cn/privacy/)); delete the account whenever you want.

This is a preview. We use it every day and know where it is rough; tell us where it broke for you and what you want it to do. Thanks to everyone who tried a build and reported what broke. ### 亮点

- **交接：手交给你，然后等。** 一次*交接*属于一个对话和一种手，浏览器、这台电脑、手机。智能体用新的 `hand_over` 动作发起（必须说明原因：「登录」「短信里的验证码」「确认付款」），你用「接管」发起，「完成」结束它；交接期间那个工具的每个动作都等着而不是报错，之后智能体从你留下的页面接着做，并被告知不要重做你的工作、不要输入凭据。一个 `hold` 事件，各处同一张卡：桌面端舞台（「轮到你了，完成」「我来」）、网页版浏览器视图、手机胶囊、聊天。
- **审批就在你所在的地方。** 桌面端实时舞台上有 **允许一次 / 在 <应用> 里始终允许 / 拒绝**（始终允许 = 按应用授权，可在智能体页面撤销）；主窗口被操作中的应用挡住时，一个置顶小胶囊显示同一张卡；演示手机的胶囊直接回答 **允许一次 / 拒绝**。只有提问还会打开应用。
- **能操作的浏览器（网页版）。** 浏览器视图可以接管、点击、输入、滚动、打开网址、后退，智能体等你时显示「已暂停，等你」，「完成」交还。
- **不抢屏幕的手（macOS）。** 手可以在某个应用的窗口里干活，鼠标还在你手里，截的是那个窗口，事件发给它的进程，每个应用问一次：「让 <Muse> 使用 <应用>？」（`[hands] mode = auto | screen | window`）。屏幕四周有一圈透明、可穿透点击的光晕，表情跟着指针，交接中变琥珀色；所有悬浮层和窗口本身都不会进截图。按 Quartz API 写的，维护者还没在 Mac 上试过，见升级说明。
- **聊天入口。** 飞书、钉钉、企业微信、Telegram，走厂商的长连接，不需要公网地址，照 nanobot 的设计。一个聊天一个对话，厂商允许编辑的地方回复原地流式刷新，审批用「允许 / 拒绝」或按钮回答，文件双向。陌生人的第一条消息会得到一个六位配对码，在应用里或用 `nanomuse channels approve` 批准；白名单、群策略、接收后台结果的「投递到这里」。网页版和桌面端的「设置 → 聊天入口」；`nanomuse channels login feishu` 扫码建机器人。可选依赖 `nanomuse[channels]`；Docker 镜像自带。
- **两个模型设置。** 用 NanoLika Cloud 账号时对话用 **DeepSeek V4.1 Flash**（看得懂图片，回答前会思考），手用 **Qwen 3.8 27B** 看屏幕；中继的菜单说明每个模型是给哪条线用的，各端都先读它再用自己的默认值。自己的 key 两条线都填，百炼或 OpenRouter。
- **你在哪决定怎么继续。** 账号带着 `region`；登录、引导、额度卡片、账号页和预设都把阿里云百炼排在国内账号的第一位、把 OpenRouter 排在其他人的第一位，并用一行说明为什么（百炼只接受中国大陆注册）。OpenRouter 加入各端的自有 key 预设，手机上带 OAuth 登录。
- **连接跟着账号走。** 一台设备连上的远程 MCP 服务进入账号资料，名字、地址、怎么登录；永远不带 key，其他设备列出「已在 <设备> 连接，在这台设备上登录即可使用」，登录信息预填好。
- **iPhone 补齐。** 点头像打开智能体页面（活动、审批、日常、灵魂与记忆、分享）；「把形象换成……」在聊天里接住，四个候选，可以用话选；目标、动态、点子是带调度器的真房间（前台补跑、后台刷新任务、到点本地通知：「打卡：<目标>，打开来运行」）；四页初次使用；NanoLika 设置页；走 hub 的编码智能体；iPad 也跑 Muse 外壳；249 条字符串三种语言。

- **更平实的话，到处都是。** 社区说明是「免费、开源、非营利」，说清谁付钱、留什么；star 提示说清一颗 star 的用处；你，不是您；没有感叹号；README 和九种翻译同一个口吻。
