# T-Bank 退款记账

当前结算仍仅用于 DEMO。测试入账及退款冲销不改变真实账户额度、使用账本或正式订阅。提供正式终端凭据不会自动启用正式收单或财政收据。

退款通知先验证签名、终端、订单及银行支付编号，再查询 GetState。通知金额不作为单次扣款金额；以银行当前剩余金额计算累计退款，只冲销尚未入账的差额。数据库事务同时更新钱包、订单和测试账本。重复通知、旧状态及退款后的迟到确认均不会再次扣款或重新入账。完整退款的剩余金额必须为零，部分退款的剩余金额必须介于零与原金额之间。已入账订单也可在认证状态请求时进行对账，每五秒限流；这不是后台持续轮询。

增量迁移保留已有钱包和历史入账。credited 保留历史证据，接口另行提供历史入账、累计退款及净入账金额。若余额已使用，退款可使其为负数，不通过归零隐藏欠款。完整退款的套餐不再贡献权益，其余有效购买按原确认顺序和原时间重新计算，不因退款赠送新月份；其他充值不受影响。

结算页面优先显示完整或部分退款及修正后的测试余额。已通过 54 项支付、退款、套餐与网关测试，并在真实 DEMO 终端验证 20000 -> 15000 -> 10000 -> 0 分的连续流程。之前未冲销的测试退款已修复；重复退款通知及迟到确认均未改变最终余额，真实额度未变。未构建原生安装包或容器镜像。完整说明见 payment-refunds.md。
