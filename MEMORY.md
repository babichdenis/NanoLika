# MEMORY — постоянные договорённости (все машины)

Файл для того, что не должно теряться между сессиями и машинами. Записи — только с
подтверждения владельца. Датированные; старые не переписываем, а дополняем.

## 2026-11-05. Вход и двери NanoLika

1. **Один бот.** Отдельного публичного бота нет. Аккаунт — база; Telegram/MAX, веб и
   компьютер — двери одного аккаунта, включаются по очереди.
2. **Паролей нет.** Telegram/MAX — аутентификатор (как GitHub/Яндекс). Почта появляется на
   оплате (чек по 54-ФЗ) и становится входом в веб; компьютер подключается кодом из чата.
3. **Компьютер — руки, не мозг.** Обычное сообщение исполняется на сервере; `/computer` —
   явный способ дать руки. Новый вход в аккаунт не даёт рук, пока компьютер не согласился;
   `remote_control` по умолчанию выключен.
4. **Windows-установщик:** `perMachine` (права администратора), без кастомной иконки
   деинсталлятора, приложение закрывается в `preInit` до распаковки.
5. **Тексты в боте:** «Настройки → Мессенджеры», не «Каналы». Имя человека спрашивать в
   первом ответе и запоминать. Время — по компьютеру; нет компьютера — спросить и записать.

## 2026-11-05. Эксплуатация

- **Ветка и доставка кода.** Работаем в `feat/voice-ru`. Если ssh-agent на Mac пуст и
  GitHub не принимает ключ — код на серверы возить `git bundle` (файл + `git fetch`), не
  переключать серверные клоны с их production-правками.
- **Релей: production-оверрайды.** Код релея на сервере живёт в `/opt/nanomuse/cloud/overrides/…`
  и монтируется в контейнер; правки — только туда, с бэкапом рядом. Пересборка образа не
  обязательна, достаточно `docker compose restart relay` (старт ~1,5 мин).
- **Marosensor: KSES.** Сохранение страниц с формами/SVG — только с `kses_remove_filters()`;
  после сохранения сверять длину контента и наличие `<form>/<select>`.
